# 백업·복구

## 백업 받는 법
1. 앱 **설정 > 백업·복구 > 전체 백업 받기** → `글공장-백업-날짜.json` 파일이 내려와.
2. 원고·요청·주제·상품·링크·실적·올린 파일 기록·설정·수익 모델·채널·조합표가 다 들어 있어. 이미지 정보(출처·프롬프트·비용·사진 자리 연결·카드뉴스 — 1.2.0부터), 다른 채널 기록·유입 검색어(1.4.0부터), AI 검수 의견·비용과 내 평가(`image_reviews` — 1.5.0)도 들어 있어. 1.1.2부터 서버가 1,000줄씩 나눠서 끝까지 담고, 파일 안 `counts`에 표마다 몇 줄 담았는지 적어 (앱 화면의 개수와 맞는지 비교해볼 수 있어). DB를 아직 올리지 않아서 없는 표는 빈 목록이고 `missing_tables`에 이름이 적혀.
3. 접속 코드·기기 로그인 정보는 들어 있지 않아 (보안 때문에 일부러 뺌). 이미지 파일 자체와 운영 기록(외부 API 호출 횟수, 공급자 연결 확인 기록)도 안 들어가.
4. 한 달에 한 번, 그리고 큰 정리를 하기 전에 받아두는 걸 추천해.

Supabase 공식 문서상 매일 자동 백업은 유료 요금제(Pro 이상)에만 있고, 무료 요금제는 직접 내보내서 따로 보관하라고 권해 ([Database Backups](https://supabase.com/docs/guides/platform/backups), 2026-10-21 확인). 지금 프로젝트는 무료 요금제라서 위 파일 백업을 꼭 따로 챙겨줘.

## 서버 안의 자동 백업 표
- 1.1 업데이트(마이그레이션 004) 직전 데이터가 `backup` 스키마에 그대로 복사돼 있어 (`backup.posts_20261021` 등). 앱에서는 안 보이고, 지우지 않았어.

## 복구하는 법 (앱에서 바로 하지 않음)
덮어쓰기를 잘못하면 원고가 사라질 수 있어서, 앱에는 '복구' 버튼을 만들지 않았어. 대신:

1. Claude에게 백업 파일을 주고 "이 백업으로 ○○를 되돌려줘"라고 말해 (무엇을 되돌릴지 구체적으로: 특정 원고, 특정 날짜의 실적 등).
2. Claude는 먼저 지금 상태를 새 백업으로 받아두고, 바뀔 줄을 보여준 뒤, 네가 확인하면 그 줄만 되돌려.
3. 표를 통째로 지우고 다시 넣는 방식은 쓰지 않아.

### 자주 있는 경우
| 상황 | 방법 |
|---|---|
| 원고를 휴지통으로 보냄 | 설정 > 휴지통 > 되살리기 (30일 동안) |
| 실적 파일을 잘못 올림 | 수익 > 올린 파일 기록 > 올리기 취소 (그 파일이 새로 넣은 줄은 지워지고, 그 파일이 고친 줄은 고치기 전 숫자로 돌아감) |
| 직접 넣은 실적이 틀림 | 그 줄의 '지우기' 후 다시 입력 |
| 수익 모델 설명을 잘못 고침 | 백업 파일의 programs 부분을 Claude에게 주고 그 칸만 되돌리기 |
