# 이미지 스튜디오 (1.5.1) — 설정·사용 안내

원고에 사진을 만들고·찾고·올려서 사진 자리에 연결하고, 검수한 뒤 내려받아 블로그에 직접 넣는 기능이야.
확인 날짜가 붙은 내용은 그날 공식 문서에서 직접 본 거야. 바뀔 수 있으니 숫자(가격·한도)는 설정에서 고칠 수 있게 해뒀어.
1.5.1에서 바뀐 것(상품 사진으로 장면 만들기)은 0번과 6-1번, 1.5.0에서 바뀐 것(고품질화)은 0-1번. 실제로 돌린 테스트·배포 상태는 `docs/REPORT-1.5.1.md`·`docs/REPORT-1.5.0.md`.

## 0. 1.5.1에서 바뀐 것 — 상품 사진으로 장면 만들기 (요약)
| 무엇 | 어떻게 |
|---|---|
| 들어가는 곳 | 이미지 보관함 위 **이 상품으로 장면 만들기** · 원고 이미지 칸 위 같은 버튼 · 빈 사진 자리의 **상품 사진으로 장면 만들기** · 이미지가 있는 자리의 '바꾸기' 창 ('(직접 찍기)' 자리는 빼고) · 직접 올린 사진·Pexels 사진 미리보기 |
| 두 방식 (섞지 않음) | **상품 원본 보존 합성** — 이 기기에서 상품 사진의 배경을 지우고(마스크), AI는 상품이 놓일 자리를 비운 **빈 배경만** 만들고, 앱이 원본 상품 픽셀을 그 위에 얹어 (그림자·밝기는 앱이 계산, AI에 상품 사진을 안 보냄). **AI 실사 장면 생성** — 상품 사진을 참고 사진(대상 모양 유지)으로 보내 AI가 장면 전체를 새로 그려. 결과는 'AI 합성 이미지'로 표시돼 |
| 순서 | 1 상품 사진 → 2 추가 사진(앞·뒤·옆, 3장까지) → 3 남길 영역 → 4 제작 목적 → 5 장면·방식 → 6 비율·품질·모델 → 7 예상 비용 → 8 후보 1~3장 → 9 원본과 비교 → 10 승인·부분 수정·다시 만들기·저장 → 11 원고 자리에 넣기 |
| 제작 목적 | 블로그 본문 · 블로그 대표 이미지 · 상품 상세 소개 · SNS 게시물 · 광고용 연출 이미지 (목적마다 비율·상품 크기·빛·구도가 달라 — 모든 장면에 어수선함·흠을 넣지 않아) |
| 장면 | 집 안 테이블이나 선반 · 자연광이 들어오는 실내 · 야외 환경 · 제품을 사용하는 상황 · 반려동물과 함께 있는 장면 · 깔끔한 제품 스튜디오 · 배경만 만들고 상품은 직접 배치(원본 보존 합성에서만) + 직접 적기 (상표·가격·후기·인증 표현은 막음) |
| 배경 지우기 | 이 기기 브라우저에서 U²-Netp(Apache-2.0)를 ONNX Runtime Web(MIT)으로 돌려 — 서버·외부 API를 안 불러서 **0원**, 사진이 밖으로 안 나가. 처음 한 번 약 19MB를 받아 이 기기에 저장. 칠해서 고치기(남기기·지우기·붓 크기·되돌리기), 가장자리 부드럽게·안쪽으로 깎기 |
| 원본 픽셀 | '원본 크기 그대로'를 켜고 회전이 0이면 상품 칸은 원본 사진 픽셀을 그대로 복사해 (가장자리 1~2px만 배경과 섞임). 크기를 바꾸거나 돌리면 원본 픽셀에서 크기만 다시 뽑아 — AI가 다시 그리지 않아 (줄일 때는 면적 평균으로 먼저 줄여서 작은 글자가 계단처럼 깨지지 않게). 이때는 작은 글자·버튼이 흐려질 수 있어서 검수에서 그 칸을 미리 채우지 않아. 상품 밝기·색온도를 바꾸면 그만큼 색이 달라지고, 검수에서 색 칸을 직접 확인해야 해 |
| 상품 디테일 검수 | 원본과 결과를 나란히 놓고 9칸을 봐. **9칸이 다 '괜찮아'여야 승인**되고, 승인 전에는 '사용 가능'으로 못 바꾸고 발행 준비 완료·예약·게시 완료 원고에도 못 써 (DB·서버·화면 세 곳에서 막음 — 본문에서 사라진 자리에 남은 연결·카드뉴스 배경·그 배경으로 그린 카드뉴스 PNG까지). AI 검수는 참고용 |
| 일반 AI 만들기에서도 | 진짜 상품 사진(직접 올림·Pexels)을 '대상 모양 유지' 참고 사진으로 넣으면 어느 자리든 AI 실사 장면으로 기록돼서 상품 디테일 검수를 승인해야 써 (AI가 그 상품을 다시 그리는 거라서). 상품이 아닌 사진(반려동물·사람·물건)이면 일반 자리에서는 '이 사진은 상품(제품) 사진이야'를 끄면 돼 — 'AI 합성 이미지'로만 표시되고 상품 검수 대상이 아님. 실제 상품이 보여야 하는 자리에서는 묻지 않고 늘 상품 사진으로 봐 |
| 고품질 모드 기본값 | '고품질 유료 생성' 기본 모델이 GPT Image 2.5 **Sunburst · 높음**으로 바뀜 (빠른 유료 생성은 Flare 그대로). 설정에 저장해 둔 값이 있으면 그 값을 그대로 써 — 설정에 '기본값'과 '내가 저장한 값'을 따로 보여주고 '기본값으로' 버튼이 있어. 단, 1.5.0 화면은 설정을 저장할 때마다 그때 기본값(Flare · 높음)까지 같이 저장해서, 그 값과 똑같이 저장돼 있으면 네가 고른 값이 아니라고 보고 새 기본값을 써 (저장된 값은 앱이 혼자 지우지 않고, 설정 화면에 그렇게 적어 둠). 예전 값(Flare · 높음)을 쓰고 싶으면 설정에서 그걸로 골라서 저장하면 돼 — 1.5.1 화면에서 저장한 값은 '네가 고른 값' 표시가 붙어서 그대로 써 |

## 0-1. 1.5.0에서 바뀐 것 (요약)
| 무엇 | 어떻게 |
|---|---|
| AI에 보내는 내용 | 예전처럼 모든 이미지에 같은 '생활 사진' 문구를 붙이지 않아. 먼저 **장면 설계서**(무엇을·어디서·카메라·빛·색·재질·구도·꼭 보일 것·넣지 말 것·플랫폼·비율)를 원고에서 만들고, **이미지 종류**(사진·일러스트·도식·카드뉴스 배경)에 맞는 지시문으로 바꿔서 보내. 원고에 없는 계절·날씨·장소는 넣지 않고, 먼지·주름·어수선함·가운데 피하기를 억지로 넣지 않아. 장면 설계서는 AI 만들기 창의 '장면 설계서 (고칠 수 있어)'에서 칸마다 고칠 수 있어 — **비워 두면 기본값**(원고·이미지 종류), **'없음'(또는 '-')이라고 쓰면 그 칸을 빼** (원고에서 잘못 읽은 계절·장소를 지울 때. 주 피사체는 못 뺌) |
| 이미지 종류 (프리셋 9가지) | 자연스러운 생활 사진 · 다큐멘터리·현장 사진풍 · 고급 편집 디자인 사진 · 제품 정물 사진 · 음식 사진 · 반려동물 일상 사진 · 설명용 일러스트 · 정보 전달용 도식 · 카드뉴스 배경. 원고 맥락으로 하나를 '(추천)'으로 고르고, 바꿀 수 있어 |
| 모드 4가지 | **무료·저비용 초안**(Cloudflare FLUX.2 klein) · **빠른 유료 생성**(GPT Image 2.5 Flare 보통) · **고품질 유료 생성**(GPT Image 2.5 Flare 높음 → **1.5.1부터 Sunburst 높음**) · **Gemini 고품질 생성**(Gemini 3 Pro Image 2K). 고른 모드의 실제 모델 이름·공급자·예상 비용·계산 근거를 늘 보여주고, 사용자가 고르지 않은 유료 모델로 저절로 바뀌지 않아. 모드마다 모델·품질은 설정에서 바꿀 수 있어 |
| 후보 여러 장 | 1장 · 2장 비교 · 3장 비교. 같은 설명으로 한 장씩 차례로 만들고, 고르는 건 너야 (앱이 대신 고르지 않음) |
| 진짜 제품 사진 넣기 | 참고 사진에 역할을 줘: **대상 모양 유지**(진짜 제품) · **구도·스타일 참고** · **배경·장소 참고**. 진짜 제품 사진을 '대상 모양 유지'로 넣으면 실제 상품이 보여야 하는 자리에도 만들 수 있고, 결과는 **'AI 합성 (실제 사진 참고)'** 으로 표시돼 |
| 고치기·수정 이력 | '조명만 더 자연스럽게'처럼 말로 고쳐. 원본은 덮어쓰지 않고 새 이미지로 만들고, 미리보기 '수정 이력'에서 원본부터 고친 것까지(누가·어떤 모델·얼마) 보여줘. 'AI 합성' 이미지를 고친 결과도 'AI 합성'으로 남아 |
| 다시 만들기 | 고친 이미지면 같은 원본을 같은 지시로 다시 고치는 창을 열어. 새로 만든 이미지면 그때 쓴 참고 사진(역할)·이미지 종류·고친 장면 칸을 되살려 (다른 글 보관함에서 고른 사진도 불러오고, 고친 'AI 합성'은 원본의 제품 사진으로). 지워져서 못 찾은 사진은 빠졌다고 알려줘 |
| AI 검수 (참고용) | 만든 이미지를 AI가 보고 항목별 의견(괜찮아·확인 필요·판단 어려움 + 이유 + 확신 정도), 불확실한 점, 고칠 점을 줘. 품질 보증 아님 — 지우거나 대신 고르지 않아 |
| 모델 비교 | 같은 설명·비율·참고 사진으로 2~3개 모드를 한 번씩 만들고 시간·비용과 같이 보여줘. 내 평가(글과의 일치도·자연스러움·형태와 디테일·구도·AI 티·게시용 가능)는 AI 평가와 따로 저장 |
| 공급자 | OpenAI·Cloudflare에 **Google Gemini API**를 더함. 앱이 모르는 모델 이름은 어느 공급자로도 보내지 않고, 종료된 모델(gpt-image-1)은 막아 |

## 2. 필요한 Supabase Secrets (이름만 — 값은 절대 저장소·채팅·앱에 넣지 마)
| 이름 | 쓰는 곳 | 없으면 |
|---|---|---|
| `CF_ACCOUNT_ID` · `CF_API_TOKEN` | **무료** AI 이미지 (기본 모델 `cf-flux-2-klein-4b`), 무료 AI 검수 (Gemma 4) | 무료 모드·무료 검수가 잠기고 '키 없음'으로 이유를 보여줌 |
| `OPENAI_API_KEY` | (선택·유료) GPT Image 만들기·고치기·참고 사진, GPT-5.6 luna 검수 | 그 모드가 잠기고 이유를 보여줌. 사진 검색·올리기·카드뉴스는 그대로 됨 |
| `GEMINI_API_KEY` (1.5.0) | (선택·유료) Gemini 이미지 만들기·고치기·참고 사진, Gemini 3.5 Flash-Lite 검수 | Gemini 모드가 잠기고 이유를 보여줌 |
| `PEXELS_API_KEY` | 실제 사진 검색 | 사진 검색이 잠기고 '직접 올리기'로 안내. 나머지는 그대로 됨 |
| `EDGE_WALL_SECONDS` (선택) | 서버 일꾼 하나가 일하는 최대 초 | 안 넣으면 150 (무료 요금제). 유료 요금제로 바꾸면 400 |

`SUPABASE_URL`·서버 키는 Supabase가 자동으로 넣어줘서 따로 할 일 없어. 키는 서버(Edge Function)만 읽고, 앱 화면에는 '있음/없음'만 와.
Secrets는 프로젝트에 한 번만 넣으면 서버 함수 두 개(`blog-app`, 생성 전용 `blog-gen`)가 같이 써.

**'키 있음'과 '연결 확인'은 달라.** 설정 > 이미지의 공급자 줄에는 세 가지를 따로 보여줘: 서버에 키가 있는지 · '연결 확인'(이미지를 만들지 않고 키와 모델을 공급자에 물어본 결과, 돈 안 듦) · 실제로 만들어 본 마지막 성공·실패. 모델 이름을 설정에 넣은 것만으로는 '연결됨'이라고 하지 않아.

생성·편집 기본 모델은 **바꿨을 때만** 저장해. 그래서 예전에 고른 모델이 공급자에서 종료돼도(새로 저장은 막힘) 한도·예산 같은 다른 칸은 그대로 저장돼 — 종료된 모델은 화면에 '공급자가 종료한 모델 (바꿔줘)'로 보여.

**여러 장(후보·비교)은 한 장씩 차례로** 만들어 (DB가 동시에 두 장을 막아서). 첫 장을 보내기 전에 남은 장 수·예상 비용으로 하루 한도·예산·한 번 상한을 미리 확인해서, 중간에 한도에 걸려 반만 만들어지는 일을 줄여. 창을 닫으면 지금 만드는 장까지만 끝내고 남은 장은 안 만들어 (돈도 안 나감). 중간 장이 한도·예산·오류로 멈추면 만든 장은 고를 수 있게 남기고, 'n장 중 m장만 만들었어'와 멈춘 이유, 보내지 않은 장(돈 안 나감)을 알려줘.
예약 셈: 후보(같은 모델)는 '이번 장 예상 × 남은 장 수', 모델 비교는 장마다 모델이 달라서 화면이 보낸 남은 장 합계로 미리 확인해 — 어느 쪽이든 이번 장 예상보다 적게 잡지 않고, 장마다 보낼 때 그 장의 예상 비용으로 예산·상한을 다시 확인해.

**비용 상태 뜻** — 실제 청구액을 공급자에서 자동으로 가져올 방법이 없어서 이렇게 나눠:
| 상태 | 뜻 |
|---|---|
| 예상 | 요청 전에 계산한 값 |
| 사용량 기준 | 공급자가 응답에 준 사용 토큰 × 가격표 (OpenAI `usage`, Gemini `usageMetadata` — 이미지 출력·글 출력·생각 토큰을 따로 셈. 이것도 계산값이지 청구서가 아님) |
| 청구액 확인 | 네가 공급자 사용량 화면(OpenAI https://platform.openai.com/usage · Google AI Studio https://aistudio.google.com/usage)에서 보고 직접 넣은 값 |
| 청구 없음 | 청구 안 된 걸 확인함 (0으로 셈). 무료 플랜 Cloudflare는 늘 청구 없음 |
| 확인 필요 | 시간 초과·중간에 멈춤·만든 뒤 안전 검사에 걸림처럼 청구됐는지 모르는 경우 → 사용량 화면에서 확인하고 고쳐줘 |
합계는 기록마다 '청구액 확인 > 사용량 기준 > 예상' 순으로 가장 정확한 값을 써. 예상과 실제는 다를 수 있어.

**수익 통계와의 관계** — 이미지 비용(생성 + AI 검수)은 실적의 '비용' 칸과 **따로** 셈. 실적 입력의 '비용' 칸에 이미지 비용을 또 적으면 두 번 빠지니까 적지 마.

**남용 막기** — 생성 버튼을 직접 눌러야 하고, 누르기 전에 공급자·모델·장수·크기·품질·예상 비용과 근거·오늘 남은 횟수·남은 예산이 보여. 같은 버튼을 여러 번 눌러도 요청 번호가 같아서 한 번만 만들어. 실패는 저절로 다시 시도하지 않아 (두 번 청구 방지).

## 6. 진짜 제품 사진으로 만들기 (참고 사진)
1. 진짜 제품 사진(직접 찍은 사진이 제일 좋아)을 **파일 올리기**로 보관함에 넣어 (쓸 권한 확인 칸 필수).
2. 그 사진 미리보기에서 **'이 사진을 참고해서 AI로 새로 만들기'** — 또는 AI 만들기 창의 '참고 사진 (n)'에서 고르거나 올려.
3. 역할을 **대상 모양 유지**로 둬 (실제 사진은 처음부터 이 역할). 구도만 따라 하고 싶으면 '구도·스타일 참고', 장소만이면 '배경·장소 참고'.
4. 결과는 **'AI 합성 (실제 사진 참고)'** 으로 표시되고, 블로그에 올릴 때 사진 아래에 넣을 문구도 '실제 사진을 참고해 AI로 만든 연출 이미지 (실제 사용 사진 아님)'로 바뀌어.
- AI는 제품을 **다시 그리는 거라서** 작은 글자·로고·버튼 모양이 바뀔 수 있어. 결과 창·미리보기에 '참고한 제품 사진과 모양·글자·버튼이 같은지' 확인 항목이 뜨고, AI 검수에도 '참고 사진과 같은지' 항목이 들어가. 다르면 쓰지 마.
- **'(직접 찍기)' 자리에는 참고 사진을 넣어도 AI로 못 만들어** — 실제로 해본 것처럼 보이는 사진을 AI로 만들지 않으려고.
- 공식·쇼핑몰 사진은 저작권이 있어서, 참고 사진으로 쓰기 전에 그 사진의 이용 조건을 확인해줘.
- 무료 모델(FLUX.2 klein)은 참고 사진을 512px보다 작게 받아 (공식 제한). 앱이 원본은 그대로 두고 500px 안의 작은 사본을 한 번 만들어 서버에 올려 둬. 작은 글자·로고는 거의 안 남으니 모양을 크게 지켜야 하면 유료 모델이 나아.
- 직접 올린 사진·실제 사진 자체를 AI로 '고치기'는 안 돼 (실제와 다른 '진짜 같은 사진'이 될 수 있어서). 참고 사진으로 넣어 새로 만들면 'AI 합성'으로 따로 남아.
- 진짜 사진으로 치는 건 **직접 올린 사진·Pexels 사진**뿐이야. AI가 만든 이미지를 '대상 모양 유지'로 넣어도 제품 모양 자리는 안 열려 (진짜 제품 모양이 아니라서). 이미 'AI 합성'인 이미지를 고치는 건 돼 — 결과도 'AI 합성'.

## 6-1. 상품 사진으로 장면 만들기 (1.5.1)
상품 사진 하나로 블로그·SNS·광고용 장면을 만들어. **두 방식을 목적에 맞게 골라** — 상품 모양이 그대로여야 하면 원본 보존 합성, 자연스러운 연출이 더 중요하면 AI 실사 장면.

| | 상품 원본 보존 합성 | AI 실사 장면 생성 |
|---|---|---|
| AI가 하는 일 | 상품이 놓일 자리를 비운 **빈 배경**만 만듦 (상품 사진을 AI에 안 보냄) | 상품 사진을 참고해 **상품까지 장면 전체를 새로** 그림 |
| 상품 | 원본 사진 픽셀 (이 기기에서 배경을 지우고 얹음) | AI가 다시 그린 상품 — 작은 글자·로고·버튼·구성품이 달라질 수 있어 |
| 표시 | '원본 보존 합성 (상품 사진 + AI 배경)' · 사진 아래 문구 '※ 원본 보존 합성 — 실제 상품 사진에 AI로 만든 배경을 합성한 이미지 (실제 사용 사진 아님)' | 'AI 합성 이미지 (실제 사진 참고)' · '※ AI 합성 이미지 — 실제 사진을 참고해 AI로 만든 연출 이미지 (실제 사용 사진 아님)' |
| 어울리는 곳 | 상품 상세 소개, 광고, 제품 모양이 중요한 자리 | 생활 장면, 사용 상황, 분위기 사진 |
| 한계 | 배경과 상품의 빛·각도가 다르면 어색할 수 있어 (그림자·밝기·위치를 직접 맞춰) | 상품 디테일이 같다는 보장이 없어 — 검수 필수 |

1. **상품 사진** — 직접 올리기(쓸 권한 확인 칸 필수) 또는 보관함에서 (직접 올린 사진·Pexels 사진만. AI 이미지·합성 이미지는 원본 상품 사진이 아니라서 못 골라). 상품 이름 칸은 보관함 설명·대체 텍스트에만 쓰고 AI에는 안 보내 (이름을 보면 AI가 글자를 지어낼 수 있어서). 원본 사진은 고치지 않고 그대로 남아.
2. **추가 사진** (선택, 3장까지 — 앞·뒤·옆) — AI 실사 장면에서만 같이 보내.
3. **남길 영역** — '자동으로 배경 지우기 (이 기기에서 · 무료)'를 누르면 분홍색 = 지울 곳으로 보여줘. 틀린 곳은 '칠해서 고치기'(남기기·지우기, 붓 크기, 되돌리기 8번). 흰·단색 배경이면 '간단히'도 돼. '이 영역 저장'은 마스크 PNG를 따로 저장해 (돈 안 듦). 다음에 같은 사진을 고르면 '저장해 둔 영역 쓰기'. 원본 보존 합성에만 필요하고, AI 실사 장면은 건너뛰어도 돼.
4. **제작 목적** · 5. **장면과 방식** — 위 두 방식 중 하나와 장면 7가지 중 하나 (+ 직접 적기). 상품 사진을 찍은 각도(정면 눈높이·살짝 위에서·바로 위에서)와 놓을 자리(가운데·왼쪽·오른쪽)는 배경이 상품 사진과 맞게 하려고 물어봐.
6. **비율·품질·모델** — 원본 보존 합성은 배경만 만들어서 '보통'이면 충분해. 무료 모델로 AI 실사 장면을 고르면 '참고 사진을 500px보다 작게 받아서 작은 로고·글자·버튼이 안 남을 수 있어'를 만들기 전에 보여줘.
7. **예상 비용** — 공급자·모델·크기·품질·예상 비용과 계산 근거, **배경 지우기: 0원 (이 기기에서 처리 — 외부 API 안 씀)** 줄을 따로 보여줘.
8. **후보 1~3장** — 버튼에 장수와 합계 예상이 보이고, 누를 때만 만들어 (같은 요청 번호로 한 장씩).
9. **원본과 비교** — 원본 보존 합성은 배경마다 상품을 얹어 본 미리보기, AI 실사 장면은 원본과 나란히.
10. **맞추기·저장·승인** — 원본 보존 합성: 사진을 끌어서 위치, 크기, 회전, 그림자(진하기·퍼짐·빛 방향), 밝기·색온도(상품·배경 따로), 가장자리(부드럽게·안쪽으로). '합성 저장 (새 이미지로)'는 원래 크기로 다시 그려 PNG(다시 압축 안 함)로 저장해 — 다시 저장하면 또 새 이미지(예전 것은 그대로). 배경만 고치기(부분 수정)는 배경을 고친 새 배경에 같은 위치·크기로 다시 얹어 (상품은 다시 그리지 않음). AI 실사 장면: 부분 수정은 '상품은 그대로 두라'를 같이 보내고 원본 상품 사진도 다시 참고로 보내. 둘 다 **상품 디테일 검수**에서 승인해야 '사용 가능'.
11. **원고 자리에 넣기** — 본문 사진 자리·대표 이미지·SNS 자리. '(직접 찍기)' 자리에는 안 넣어. 발행 준비 완료(또는 예약·게시) 원고에는 승인한 뒤에만.

**상품 디테일 검수** (이미지 미리보기·장면 만들기 화면의 '원본과 비교해서 검수·승인')
- 원본 상품 사진과 결과를 나란히 놓고 9칸: 상품 외형과 비율 · 색상과 소재 · 버튼·포트·마감 · 라벨·로고·인쇄 · 구성품의 수와 배치 · 상품 크기와 원근감 · 배경에 자연스럽게 놓였는지 · 불필요한 물체나 가짜 문구 · 게시할 때 상품 정보와 모순되는지. 칸마다 괜찮아·문제 있어·모르겠어.
- 위에 방식이 크게 표시돼 (원본 보존 합성 / AI 재생성). 원본 보존 합성은 픽셀을 다시 만들지 않아서 외형·색·버튼·글자 4칸을 '괜찮아'로 미리 채워 (상품 밝기·색온도를 바꿨으면 색은 안 채움). AI 실사 장면은 아무것도 미리 채우지 않고 '제품 외형·제품명·로고·인쇄 글자가 원본과 다를 수 있어'를 크게 보여줘.
- **9칸이 다 '괜찮아'여야 승인**돼. 승인하면 '사용 가능', 승인을 풀면 '검수 전'으로 돌아가고 그 이미지를 쓰는 발행 준비 완료·예약 원고는 '검수 필요'로 돌아가.
- 승인 전에는: 미리보기의 '사용 가능'을 누르면 검수 창이 열리고, 내려받아도 '사용 가능'이 되지 않아(버튼에 '상품 검수 전'), 원고 검사에 오류('상품 디테일 검수를 승인하지 않은 상품 이미지가 n곳')가 떠서 발행 준비 완료로 못 바꿔. 서버와 DB도 같은 규칙으로 막아.
- 'AI 검수 (참고용)'는 아래에 접혀 있어 — 합격 보증이 아니라 의견이야. 승인은 네가 해.
- 미리 채우는 칸: 원본 보존 합성은 외형·색을 미리 '괜찮아'로 채우고, '원본 크기 그대로'·회전 0이면 버튼·글자까지 채워 (줄이거나 돌리면 작은 글자·버튼이 흐려질 수 있어서 직접 확인). 상품 사진이 아주 커서(긴 변 2,560px 넘음) 줄여 읽었으면 '원본 크기 그대로'여도 버튼·글자는 직접 확인해.
- 카드뉴스 배경으로 새로 고르는 상품 장면 이미지는 승인한 것만 돼 (카드 PNG를 그릴 때도 같음). 카드 PNG에는 그릴 때 쓴 배경이 기록돼서, 나중에 그 배경의 승인을 풀면 그 카드를 넣은 원고와 그 배경을 쓰는 카드뉴스의 원고도 발행 준비 완료로 못 바꾸고(이미 발행 준비·예약이면 '검수 필요'로) — 다시 승인하거나 승인한 배경으로 카드를 다시 만들어줘. 같은 배경으로 문구만 고치는 건 돼. 이 경우는 원고 검사 화면에는 바로 안 보이고 발행 준비로 바꿀 때 알려줘. 원본 보존 합성을 배경으로 쓴 카드는 캡션에 '배경은 원본 보존 합성 이미지 — 실제 상품 사진에 AI로 만든 배경을 합성'과 상품 사진 출처가 같이 들어가.
- 이미 게시한 원고는 승인을 풀어도 그대로야. 그 원고에서 사진 순서를 바꾸거나 같은 이미지를 다시 연결(용도 바꾸기 등)하는 건 되고, 승인 안 한 다른 상품 이미지를 새로 넣는 건 막아.

**기록** — 합성 이미지마다 방식(`composite_mode`), 원본 상품 이미지, 배경 이미지, 마스크, 위치·크기·회전·그림자·밝기 설정, 배경 생성 비용(그 배경의 생성 기록)과 배경 지우기 비용(0원, '청구 없음')이 따로 남아. AI 실사 장면은 원본 상품 이미지와 생성 비용. 보관함 미리보기에 원본 상품 사진·AI 배경 그림과 합성 설정·마스크·비용 줄로 보여줘.

**알아둘 것**
- 처음 배경 지우기는 도구(약 19MB)를 받느라 Wi-Fi에서 권해. 그다음부터는 이 기기에 저장된 걸 써. 받은 파일은 해시로 확인한 뒤에만 저장하고, 저장된 것도 쓸 때마다 확인해 — 다르면 쓰지 않고 '간단히'로 하고 다음에 다시 받아.
- 원본 보존 합성은 그 상품용으로 만든 빈 배경에만 얹을 수 있어 (AI 실사 장면이나 다른 AI 이미지 위에는 안 돼). 만드는 중에는 방식을 바꿀 수 없어.
- 버튼을 두 번 눌러도 한 번만 보내. 영역을 저장하는 동안 칠한 건 '아직 저장 안 함'으로 남고, 합성은 서버에 저장한 그 영역으로 그려.
- 마스크는 긴 변 1,600px까지로 만들고 저장해 (상품 사진이 더 크면 같은 비율로). 합성할 때 상품 사진 크기로 늘려 써.
- 합성 결과 크기는 고른 비율로, 긴 변이 목적별 크기(블로그 본문·대표·광고 1,600 · 상품 상세 1,200 · SNS 1,080)와 배경 해상도의 1.25배 중 작은 쪽이야 (배경을 너무 늘리지 않게).
- 상품을 원래 사진보다 크게 늘리면 '흐려 보일 수 있어', 그림 밖으로 나가면 '조금 나갔어'를 보여줘.
- 1.5.2부터 화면을 새로 고쳐도 이 기기에 저장한 진행 상황으로 '이어서 작업하기'를 할 수 있어 (아래 6-2). 저장한 마스크·배경·합성 이미지는 전처럼 보관함에 남아.
- 아이폰 Safari·PC Chrome에서 돼야 하지만, 실제 아이폰에서는 아직 안 돌려 봤어 (검증 안 됨). 안 되면 '간단 모드'나 '간단히' 배경 지우기로.

## 6-2. 1.5.2에서 바뀐 것 — 상품 장면 고도화
**첫 화면 세 방식** — '무엇을 만들까?'에서 고름. 결과와 한계를 한 줄씩 보여줘.
| | 상품 원본 보존 합성 | AI 실사 장면 생성 | 배경만 만들기 |
|---|---|---|---|
| 결과 | 내 상품 사진 픽셀 그대로 + AI가 만든 빈 배경 | AI가 상품 사진을 보고 장면 전체를 새로 그림 | 상품이 놓일 빈 배경만 보관함에 |
| 한계 | 빛·그림자·크기를 맞춰야 해 (자동 추천 있음) | 작은 글자·로고·버튼이 바뀔 수 있어 — 원본과 꼭 비교 | 상품은 나중에 얹거나 다른 곳에서 씀 |
| 상품 사진을 AI에 | 안 보냄 | 보냄 (참고 사진) | 안 보냄 (빛·각도 추정에만 이 기기에서 씀) |

**단계** — 1 사진 · 2 추가 사진 · 3 남길 영역 · 4 장면 설정 · 5 만들기 · 6 고르기 · 7 맞추기·저장 · 8 검수·넣기. 위의 진행 줄을 누르면 그 단계로 가. 장면 설정은 목적·장면·놓을 자리·모델만 바로 보이고, 각도·빛·색·밝기·비율·품질·직접 적기는 '고급 설정'에 접혀 있어. 예상 비용은 만들기 버튼 바로 위에.

**작업 이어 하기** — 진행 상황을 **이 기기 브라우저(IndexedDB)에만** 저장해. 서버로 안 보내.
- 저장하는 것: 상품·추가 사진·마스크·배경 후보·고른 후보·합성 결과의 **이미지 번호**와 설정(방식·목적·장면·각도·자리·빛·색·밝기·비율·모델·품질·장수·위치·크기·그림자·밝기). 손으로 고쳤는데 아직 서버에 저장 안 한 마스크만 PNG로 같이 둬 (보통 수십~수백 KB).
- 저장하지 않는 것: 사진 파일, 서명 주소(다시 열 때 번호로 새로 받음), 접속 코드·세션·키.
- 다시 열면 '하던 작업이 있어 — 이어서 작업하기 / 새로 시작하기'. 새로 시작하기는 이 기기의 기록만 지워 (만든 이미지는 보관함에 그대로).
- 보존: 마지막으로 고친 뒤 14일, 다 끝낸 작업(검수 승인·자리에 넣음)은 3일, 많아야 8개. 로그아웃하면 바로 지워. Safari는 이 사이트를 7일 동안 안 쓰면 브라우저 저장소를 먼저 지울 수 있어 (홈 화면 앱은 따로 셈).
- 저장 공간이 모자라거나(사생활 보호 모드 등) 저장이 안 되면 화면 위에 알려주고 작업은 계속돼.

**배경 지우기 안정성 (아이폰 포함)**
- 따로 **일꾼(Web Worker)** 에서 돌려서 처리하는 동안 화면이 안 멈춰. 일꾼을 못 쓰는 옛 브라우저는 예전처럼 화면 쪽에서 (그때는 잠깐 멈출 수 있다고 알려줌).
- 진행 줄: 도구 받는 중(n/19MB, 처음 한 번) → 준비 → 배경 지우는 중 + 초, **취소** 버튼. 90초(정밀하게 150초) 넘게 답이 없으면 멈추고 알려줌.
- 끝나고 45초 동안 안 쓰면, 화면을 내리면(다른 앱으로), 합성을 저장하기 전에 도구를 메모리에서 내려.
- **간단 모드**: 사진을 긴 변 1,600px(보통 2,560px)·영역 1,024px(보통 1,600px)·미리보기 600px로 작게 처리. 기기 메모리가 2GB 이하라고 알려 주는 브라우저(크롬 계열), 처리 중에 페이지가 꺼졌다 다시 열린 경우(아이폰이 메모리가 모자라면 페이지를 다시 읽음), 처리가 너무 오래 걸린 경우에 저절로 바뀌고, 3번에서 직접 바꿀 수도 있어. 아이폰 Safari는 기기 메모리를 알려 주지 않아서 처음엔 보통 크기로 해.
- WebAssembly SIMD가 없는 브라우저(iOS 16.4 전)는 도구를 못 돌려서 '간단히'(테두리 색)와 직접 칠하기만 돼 — 그렇다고 알려줌.
- **정밀하게 (2단계)**: 상품 부분만 잘라서 한 번 더 봐. 시간은 두 배쯤. 상품이 사진을 거의 채우면 한 번만. 두 결과가 많이 다르면(다른 물건을 잡았을 수 있음) 처음 결과를 그대로 두고 알려줘. 값은 비교 시험에서 고름 (`docs/maskbench-1.5.2.md`).
- **간단히** (모델 없이): 1.5.2에서 고쳤어 — 예전엔 부드러운 윤곽 틈으로 상품 안까지 번지는 일이 많았어. 지금은 테두리의 배경 색을 따라가다 윤곽에서 멈춰. 흰·단색 배경 사진에만 맞고, 무늬 있는 배경은 배경이 많이 남아.
- **영역 품질 (추정)**: 좋아 보임 / 확인 필요 / 고쳐야 함 + 점수와 이유 (떨어진 조각·가장자리에 닿음·흐릿한 가장자리·경계가 사진 윤곽과 안 맞음·안쪽 구멍). 정답을 모르고 보는 점수라 높아도 확대해서 확인해.
- 고치기: 보기(지울 곳 표시·흰 바탕·검은 바탕 — 가장자리 잔상 확인), 확대(2배·4배, 칠하기를 끄면 밀어서 움직임), 되돌리기·다시 하기(마스크 크기에 따라 3~12번), 가장자리 다듬기(경계 근처만 사진 윤곽에 맞춤), 1칸 넓히기·좁히기, 작은 조각·구멍 정리.
- 실패해도 원본 사진은 그대로야 (읽기만 함).

**빛·원근·그림자 자동 추천** (7번 '자동 추천')
- 상품 사진(+마스크)과 고른 배경을 이 기기에서 작게 줄여 **픽셀만 보고 추정**해 (0원, 밖으로 안 보냄). 실제 렌즈·광원·카메라 각도를 안다고 하지 않고, 확신이 낮으면 '확신 낮음'.
- 상품 사진: 상자·비율·모양(세로로 긴·네모난·옆으로 넓은), 빛 방향(상품 안 밝기 차이 + 원래 그림자 — 둘이 다르면 '모름'), 색 느낌(배경의 무채색 칸), 밝기. 4번 장면 설정의 빛·색·밝기를 이 값으로 미리 고르고 '(추정)'으로 표시 → **빈 배경 프롬프트**에 카메라 시점·표면 높이·바닥 원근·빛 방향·그림자 방향·밝기·색온도·상품 모양을 넣어.
- 배경: 빛 방향·색·빛의 세기(대비)·상품을 놓기 좋은 빈 자리(무늬가 적은 곳).
- 추천: 크기(목적별, 넓은 상품은 폭 80% 안, 원래 사진보다 크게 늘리지 않게), 위치·바닥 닿는 높이(빈 자리를 확실히 찾았을 때만), 그림자 방향(배경 빛 반대쪽)·진하기·퍼짐, 밝기·색온도 차이(기본은 **배경 쪽**을 맞춰서 상품 픽셀은 그대로 — '상품 쪽을 바꿔서 맞추기'를 고르면 상품 색이 달라져서 검수에서 색 칸을 직접 확인).
- '추천값 적용'을 눌러야 바뀌고(무엇이 왜 바뀌는지 줄마다 — 위치·슬라이더를 바꾸면 목록도 지금 값 기준으로 다시 계산), 누를 때 **목록에 있는 칸만** 바꿔 (손으로 맞춘 다른 칸은 그대로). '적용 전으로'로 돌아갈 수 있고, 적용한 뒤에도 슬라이더로 고칠 수 있어. 빛 방향이 상품과 배경에서 반대면 배경을 다시 만들라고 알려줌.
- 4번 장면 칸(빛·색)에는 **확신이 보통인 추정만** 미리 채우고 '(추정)'으로 표시해. 확신이 낮은 추정은 글로만 보여주고 배경 요청에는 안 넣어. 네가 직접 고른 칸('지정 안 함' 포함)은 영역을 고쳐 다시 추정해도 그대로야.
- 미리보기는 슬라이더를 움직이거나 배경을 바꾸면 바로 다시 그려. 상품 레이어 준비(마스크 → 가장자리 → 색 정리)는 마스크·가장자리 설정이 바뀔 때만 다시 해 (상품 픽셀을 불필요하게 다시 처리하지 않음).

**합성 저장 안정성**
- 저장 전에 결과 크기(가로×세로)와 PNG 예상 크기, 서버 한도(합성 12MB — 서버 코드 한도와 보관함 버킷 한도 25MiB 중 작은 쪽을 서버가 알려줌)를 보여줘.
- 그린 PNG가 한도를 넘으면 **올리지 않고** '긴 변 n px로 줄여서 저장'을 권해 (PNG는 무손실이라 더 압축할 수 없음 — 손실 압축(JPEG)으로 바꾸지 않음).
- 무손실 최적화: 합성 결과는 모든 칸이 불투명이라 투명도 칸 없는 PNG로 만들어 (브라우저에 따라 파일이 작아짐 — 픽셀 값은 같은지 화면 시험으로 확인).
- 올리는 동안 '올리는 중… n%'. 실패하면 이유(인터넷 끊김·시간 초과·저장소 실패·저장 공간·DB 업데이트 필요 등)와 **'다시 저장 (같은 요청)'**: 같은 요청 번호로 보내서, 사실은 저장됐는데 답만 못 받은 경우엔 그 이미지를 돌려받고(두 장 안 생김), 파일만 올라가고 기록이 안 됐으면 같은 자리에 덮어써.
- '그만두기'를 누르면 그 요청 번호의 합성 파일만 정리해 (서버가 `composite/` 아래, 어떤 이미지 기록도 가리키지 않고 **올린 지 15분이 넘은** 그 번호의 파일만 지움 — 아직 저장 중일 수 있는 파일은 다음에 다시. 원본 상품·배경·마스크는 경로가 달라서 못 지움).
- 저장한 그대로면 버튼이 '저장됨 ✓'로 잠겨서 같은 합성이 또 생기지 않아. 위치·슬라이더를 바꾸면 바로 '합성 저장'으로 돌아와.
- 배경 지우기·저장·만들기가 도는 동안에는 상품 사진을 바꿀 수 없어 (끝난 결과가 새 사진에 붙지 않게). '간단 모드'를 켜고 꺼도 만든 영역·후보는 그대로야 (다음 배경 지우기부터 적용).
- 저장하기 전에 배경 지우기 도구를 내려서 메모리를 확보하고, 그리다가 메모리가 모자라면 간단 모드를 권해.

**상품 검수 화면**
- 비교: 나란히 / **밀어서 비교**(가운데 선을 밀어서 원본과 결과를 겹쳐 봄) / **상품 부분 확대**. 원본 보존 합성은 저장할 때 남긴 '상품이 그려진 자리'와 마스크의 상품 상자로 같은 부분을 잘라 맞춰 보여줘. AI 실사 장면은 상품 위치를 몰라서 전체를 대략 겹쳐.
- 원본 보존 합성 + 원본 크기 그대로 + 회전 0 + 상품 밝기·색 그대로면 **'원본과 픽셀 비교하기'**: 상품 안쪽 칸을 원본 사진과 한 칸씩 비교해 'n칸 중 n칸이 같아'로 보여줘 (이 기기에서). 그래도 승인은 사람이.
- 칸마다 볼 곳이 방식마다 달라: 원본 보존 합성은 떠 보이는지·접촉 그림자·가장자리 잔상·잘린 구성품·배경/그림자는 AI·앱이 만든 것이라는 점, AI 실사 장면은 아홉 칸 모두 원본과 직접 비교(글자는 한 글자씩).
- **후기 사진으로 오해될 가능성**: 후기 글·써본 경험을 말하는 자리·사용 장면·반려동물 장면이면 '있음/높음'으로 표시 (AI 실사 장면이면 더 높게).
- AI 검수는 전처럼 참고만 (자동 승인 없음).

**공급자 비교** (5번 '공급자 비교 (같은 상품·장면으로)')
- 같은 상품 사진·장면 설정·비율로: 무료 Cloudflare 빈 배경 2장(원본 보존 합성) · 무료 Cloudflare AI 실사 장면 1장 · OpenAI GPT Image 2.5 Sunburst(높음) 실사 장면 1장 · Gemini 3 Pro Image(2K) 실사 장면 1장.
- 키가 없는 줄은 고를 수 없고, **유료 줄은 줄마다 '승인'을 체크해야** 보내. 합계 예상·하루 횟수·한 달 예산·한 번 상한을 먼저 확인해. 모델이 못 받는 것(참고 사진 수 초과)이면 그 줄은 막아.
- 결과: 원본 보존 합성 줄은 추천값으로 상품을 얹어 본 미리보기, 실사 장면 줄은 결과. 줄마다 생성 시간·비용(생성 기록 그대로)과 평가 9칸(자연스러움·외형 보존·구도·조명·그림자·색감·원고 일치·AI 티·게시 가능성) — 평가는 네가 매겨. 만든 이미지는 후보에도 들어가.
- 한두 번 비교로 어느 모델이 늘 낫다고 단정할 수 없어.

**원고 자리 정보·반복 막기** (원고 이미지 칸의 사진 자리마다)
- 왜 필요한지(소제목·앞뒤 문장), 보여줄 것, 직접 찍어야 하는지('(직접 찍기)'), 실제 상품이 보여야 하는지('(제품 사진)'·버튼·라벨 같은 말 — 원본 보존 합성 권장), AI 장면으로 대신해도 되는지와 추천 종류, 상태(이미지·검수·게시 준비).
- 같은 이미지를 본문 두 자리 이상에 넣으면 그 자리들과 발행 전 검사에 알려주고, 앱에서 새로 넣을 때(보관함에서 고르기·다른 자리에 연결·상품 장면 넣기)는 서버가 거절해 → 그 이미지가 있는 **자리를 모두** 보여주고 '옮겨 오기'를 고를 수 있어 (옮기면 그 자리들에서는 빠지고 이미지는 보관함에 그대로). 대표 이미지·SNS 자리는 본문 사진을 그대로 써도 돼서 따지지 않아. 같은 파일을 다시 올리거나 같은 Pexels 사진을 다시 고른 경우는 막지 않고 알림·발행 전 검사로 알려줘.
- 실제로 찍지 않은 사진을 직접 찍은 사진으로 표시하지 않아 ('(직접 찍기)' 자리에는 합성·AI 이미지가 안 들어감 — 전과 같음).

## 7. 저장·보안
- 파일은 Supabase Storage **비공개 버킷 `post-images`** (서버만 올리고 읽음). 앱은 로그인한 기기에만 **1시간짜리 서명 주소**로 보여줘. 무료 모델용 작은 사본도 같은 버킷의 `small/` 아래에 있고, 이미지를 지우면 같이 지워. 1.5.1의 마스크는 `mask/`(PNG, 6MB까지), 합성 결과는 `composite/`(PNG, 12MB까지) 아래에 저장하고, 상품 사진을 지우면 그 마스크도 같이 지워.
- 무료 요금제 파일 저장 공간은 1GB. 앱은 900MB가 차면 새로 저장을 멈추고 알려줘 (Gemini는 결과가 클 수 있어서 20MB 여유가 있어야 시작).
- 한 파일 한도: AI가 만든 결과는 **25MB**까지 받아 (1.5.0 — Gemini 2K 결과가 PNG면 10MB를 넘을 수 있어서, DB 업데이트 017이 비공개 버킷의 한 파일 한도를 10MB → 25MB로 넓힘. 공개 여부·허용 형식은 그대로). 직접 올리기는 8MB.
- 지우기: 어느 원고(휴지통 포함)·카드뉴스에서든 쓰고 있으면 못 지워. 고친 이미지의 원본을 지워도 수정 이력에는 '지운 이미지'로 남아. 1.5.1: 남아 있는 상품 장면 이미지가 원본 상품 사진·배경으로 가리키는 이미지도 못 지워 (합성의 원본이 사라지지 않게).
- 직접 올리기: JPEG·PNG·WebP만, 8MB까지. 숨은 정보(위치·카메라)를 지우고 다시 저장. 다른 사람 사진이면 쓸 권한 확인 칸을 꼭 눌러야 올라가.
- 키는 서버 Secrets에만. 화면·HTML·JS·ZIP·로그에 넣지 않고, 공급자 오류 문구에 키처럼 생긴 글자가 있으면 가려서 저장해.

## 8. 안전장치
- AI 이미지 안에는 글자·로고를 넣지 않아 (도식은 숫자·화살표만, 카드뉴스 배경은 빈 공간 — 글자는 카드뉴스에서 앱이 그려).
- 상품 글의 '실제 사진 필요' 자리(구성품·박스·라벨·성분표·화면·버튼·'(제품 사진)' 등)는 **진짜 제품 사진을 '대상 모양 유지'로 넣거나**, **직접 찍은 사진을 올리거나**, '실제 상품이 아니라 일반 장면으로 만들게'를 체크해야 AI로 만들 수 있어 (서버도 같은 판단으로 다시 확인하고 기록에 남김).
- 실제 사용 후기·실사용 사진을 AI로 지어내지 않아 ('(직접 찍기)' 자리는 막음, 후기 사진 요청은 막음).
- AI에 같이 보내는 맥락(제목·소제목·앞뒤 문장)에서 연결한 상품 이름·브랜드·모델명·가격·인증·순위 표현을 지우고 보내.
- 장면 설계서에서 고친 칸에도 같은 금지 검사(상표·가격·후기 사진 등)를 해. 그려 달라는 칸만 봐서, '넣지 말 것'에 적은 '로고'·'글자'는 막지 않아. 고친 **주 피사체·꼭 보일 것**이 실제 상품(버튼·화면·라벨 등)을 보여 달라면 제품 모양 자리와 같은 판단을 해 (장소·구도·빛 칸의 '화면 왼쪽'·'카페 내부'·'소프트박스' 같은 말로는 막지 않아).
- 대체 텍스트·사진 검색어·AI에 보내는 장면 설명에는 '(직접 찍기)'·'(제품 사진)' 표시를 빼고 넣어 (판단할 때는 표시를 그대로 봄).
- 새 이미지는 모두 '검수 전'. AI 검수는 의견일 뿐이라 검수 상태를 바꾸지 않아 — '사용 가능'은 네가 정해.
- 상품 장면 이미지(원본 보존 합성·AI 실사 장면, 그리고 실제 상품 자리를 진짜 상품 사진 참고로 만든 AI 합성)는 **상품 디테일 검수 승인 전에는 '사용 가능'이 안 되고 발행 준비 완료·예약·게시 완료 원고에 못 들어가** (DB 트리거·서버·화면이 같이 막음, 1.5.1).
- 상품 장면 흐름에는 후기·사용 인증처럼 보이게 하는 장면이 없어 (직접 적기에 그런 말이 있으면 막음).
- AI 이미지·AI 합성·실제 사진(Pexels)·직접 올린 사진은 칸마다 표시로 구분돼.

## 9. 블로그에 넣는 법
- 미리보기 > **검수 완료하고 내려받기**: 아이폰은 공유 창에서 '이미지 저장', PC는 파일로 받아져. 여러 장은 '전부 내려받기'(PC는 ZIP).
- 파일 이름이 `키워드(없으면 제목)-사진순서-용도.jpg` 라서 순서대로 넣기 쉬워.
- 네이버 블로그·티스토리에 자동으로 올리는 기능은 **없어**. 받은 파일을 직접 올려줘.

## 무료 AI 이미지 (Cloudflare Workers AI)
- 기본 모델 `cf-flux-2-klein-4b` (FLUX.2 [klein] 4B): 만들기와 고치기를 한 모델에서, 고른 비율 그대로(긴 변 1024), 품질 '보통' 하나(단계 4 고정), 참고 사진 4장까지(512px보다 작은 사본). 공식: Cloudflare 모델 페이지·변경 기록, 가격 페이지 (2026-10-27 확인).
- FLUX는 한국어를 잘 못 알아들어서, 같은 무료 계정의 글 모델(Llama 3.3 70B)이 장면 설계서를 영어 프롬프트로 바꿔. 1.5.0부터는 이 글 모델에게도 '이미지 종류를 따르고, 설계서에 없는 계절·날씨·시간·나라·도시를 넣지 말라'고 해 (예전처럼 '폰으로 찍은 생활 사진·작은 흠·약간 어수선함'을 모든 사진에 강제하지 않음). 마지막 줄 규칙도 이미지 종류마다 달라 (사진: 로고·글자 없이, 도식: 숫자·화살표만, 카드뉴스 배경: 넓은 빈 공간).
- 무료 플랜(Workers Free)은 **하루 10,000 뉴런**까지 무료, 넘으면 오류로 실패만 하고 청구되지 않아 (매일 오전 9시에 다시 채워짐). Cloudflare를 유료(Workers Paid)로 바꾸면 넘는 만큼 청구될 수 있어 (1,000뉴런당 $0.011).
- 생성 기록은 공급자 `cloudflare`, 비용 `청구 없음`·$0으로 남아. 하루 생성 한도(설정)는 그대로 적용돼.
- 잘 나오게 쓰는 법: 사진 자리 설명은 **눈에 보이는 것**으로 (무엇이·어디에·어떤 빛). 글자·숫자가 있어야 하는 물건(포장·화면·계기판)은 피하거나 카드뉴스로.
- 예전 기본 `cf-flux-1-schnell`도 설정에서 고를 수 있어 (1024×1024 하나, 고치기·참고 사진 안 됨).
