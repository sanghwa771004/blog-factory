## 4. 필요한 Supabase Secrets 변수명
| 이름 | 용도 | 없으면 |
|---|---|---|
| `OPENAI_API_KEY` | AI 이미지 만들기·고치기 | AI만 '키 없음'으로 잠김 |
| `PEXELS_API_KEY` | 실제 사진 검색 | 사진 검색만 잠기고 직접 올리기로 안내 |
| `EDGE_WALL_SECONDS` (선택) | 서버 일꾼 최대 시간(초) | 150 (무료 요금제). 유료 요금제면 400 |
기존 `SUPABASE_URL`·서버 키는 Supabase가 자동으로 넣어줌. `ALLOWED_ORIGINS`는 그대로. Secrets는 프로젝트 단위라 서버 함수 두 개(`blog-app`·`blog-gen`)가 같이 써 — 새로 넣을 이름은 위 3개뿐.

## 6. 비용 제한 설정 방법
앱 **설정 > 이미지 (AI·사진·비용 한도)** — 자세히는 `docs/image-studio.md` 4장.
- 하루 생성 한도 기본 5장(0~50, 0이면 끔), 한 달 예산 기본 2달러(0~500), 품질 기본 보통, 모델 이름 2개, 환율(기준일·출처), 가격표.
- 이번 달 쓴 돈 + 이번 예상 비용이 예산을 넘으면 만들기 전에 막아. 하루 한도는 OpenAI까지 간 요청만 셈.
- 마지막 안전장치로 OpenAI Limits의 hard spend limit을 같이 쓰기를 권장.
- 예상 비용(보통 품질): 장당 약 0.010~0.015달러. 예상 비용과 실제 청구액은 다를 수 있어서 '예상 / 사용량 기준 / 청구액 확인 / 청구 없음 / 확인 필요'로 나눠 보여줘.

| Supabase Storage (비공개 버킷·서명 주소) | 구현 | **미실행** — 배포 전 (배포하면 임시 세션으로 올리기·서명 주소·비공개 확인을 실서버에서 해볼 계획: `tests/live/README.md` 7번) |
| Canva | 연결 안 함 (지시서대로 자체 템플릿 우선, 렌더러 자리만 나눠 둠) | — |
| 네이버 블로그·티스토리 이미지 자동 올리기 | 만들지 않음 (공식 API·권한이 확인되지 않음) | — |

## 9. 아직 수동으로 해야 하는 작업
1. **배포 승인** — 이 대화에 '배포해'라고 보내줘. 내가 DB 012를 넣을 때 Supabase 확인 창("This SQL includes destructive operations…")이 뜨면 **허용(Accept)** 을 눌러줘.
   - 실제로 지우는 건 없어: 새 표·열·함수만 더하고, 함수 `image_slot_rekey` 안에 '빈 사진 자리 줄 정리' delete 한 줄이 있어서 확인 창이 떠 (그 함수가 나중에 불릴 때 이미지 없는 연결 줄만 지움).
   - 그다음 서버 함수 두 개(`blog-app`, 생성 전용 `blog-gen`) 올리기 → 실서버 점검(키 없이 되는 것 전부 + 점검용 가짜 모델로 생성 흐름) → 앱 화면 1.2.0 올리기까지 내가 할게.
   - 확인 창이 안 뜨고 계속 취소되면: Supabase 대시보드 SQL Editor에 `supabase/migrations/012_image_studio.sql` 내용을 붙여넣고 Run → 경고가 나오면 'Run this query' (그 뒤는 내가 이어서 함).
2. **OpenAI 키** — 발급(https://platform.openai.com/api-keys) → 크레딧 충전 → 필요하면 조직 인증 → OpenAI Limits에서 한 달 hard limit 걸기 → Supabase Secrets에 `OPENAI_API_KEY`로 저장 (`docs/image-studio.md` 3장).
3. **Pexels 키** — 지금은 새 키 발급이 멈춰 있어. 열리면 받아서 `PEXELS_API_KEY`로 저장. 그 전까지는 직접 올리기.
4. **환율** — 설정 > 이미지에 원/달러 환율·날짜·출처 (원화로 보고 싶으면).
5. **첫 실제 생성 확인** — 키를 넣은 뒤 낮은 품질로 한 장 만들어 보고, OpenAI 사용량 화면의 금액을 그 기록의 '청구액 넣기'에 넣어 비교.
6. **블로그에 사진 넣기** — 앱이 대신 올리지 않아. 내려받은 파일을 사진 자리 순서대로 직접 올려.
7. **아이폰에서 한 번** — 사진 '내려받기'가 공유 창으로 열리는지(사진에 저장) 확인 — 실기기 테스트를 못 해서.

## 알려진 한계
- 실제 청구액은 OpenAI에서 자동으로 가져올 방법이 없어서, 앱이 아는 건 예상·사용량 기준까지야. 청구액은 OpenAI 사용량 화면에서 보고 직접 넣어야 '청구액 확인'이 돼.
- Supabase 무료 요금제 서버 함수는 한 번에 150초까지라, OpenAI가 아주 오래 걸리면(2분 넘게) 결과를 못 받고 '확인 필요'로 끝날 수 있어. 일꾼 남은 시간이 부족하면 돈이 나가기 전에 '서버가 바빠'로 기다렸다 다시 보내. 생성은 생성 전용 서버(`blog-gen`)로 보내서 이 대기가 줄게 했지만, 실서버에서 얼마나 줄어드는지·Supabase가 언제 새 일꾼에 넘기는지는 아직 확인 못 했어.
- AI 이미지는 '예시 삽화'야. 실제 상품 비교 글에는 허용된 실제 사진을 직접 올려야 해 (앱이 그 자리에 실제 사진 필요를 표시함).
- 카드뉴스 글꼴은 Google Fonts에서 받아. 인터넷이 안 되면 기본 글꼴로 그려져.
- 저장 공간은 무료 요금제 1GB (앱은 900MB에서 멈춤).
- 같은 서버 일꾼에서 다른 요청이 CPU·메모리 한도를 넘기면 만들던 이미지가 중간에 끊길 수 있어 (생성 전용 서버로 나눠서 드물어지게 했지만 막을 수는 없음 — Supabase 한도). 그때는 '확인 필요'로 남으니 OpenAI 사용량에서 확인해줘.
- 자동 작가가 원고를 다시 쓰면, 그 원고의 이미지 칸을 한 번 열 때 연결이 새 자리에 맞춰져 (그 전까지 원고 목록의 📷 숫자가 맞지 않을 수 있음). 내용이 통째로 바뀐 자리는 함부로 옮기지 않고 '사라진 자리'로 보여줘.
- `gpt-image-2`는 공식 가격 페이지의 Standard 표에서 가격을 확인하지 못해서 예상 비용을 넉넉하게 잡아 (실제 청구액은 직접 확인).
- 창 밖을 눌렀을 때 적던 내용 지키기는 AI 만들기·파일 올리기 창에만 있어. 다른 창은 '닫기'와 똑같이 닫혀.
- 같은 설명의 사진 자리(`[이미지: 히터 사진]`이 여러 번)는 주변 글로 자리를 알아봐. 주변 문장을 모두 새로 쓰면서 같은 설명 자리를 지우거나 넣기까지 한 경우(한 번에 둘 다)는 어느 자리였는지 알 방법이 없어서 순서대로 맞추고, 확실하지 않은 이미지는 '사라진 자리'로 남겨 (엉뚱한 자리에 붙이지 않음). 같은 문장이 여러 문단에 똑같이 반복되는 글에서는 가끔 같은 설명의 이미지끼리 자리가 바뀔 수 있어 (모의 시험 기준).
- 지우기와 연결·카드뉴스 저장이 동시에 일어날 때의 잠금(FOR SHARE)은 코드로 따져 봤고, 시험용 DB가 연결을 하나만 열 수 있어서 실제 동시 실행으로는 시험하지 못했어.
