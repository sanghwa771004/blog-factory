# 글공장 1.4.0 운영 시스템 — 보고서 (2026-10-26)

목표(사용자 요청): "AI로 글만 많이 만드는 앱이 아니라, 사람들이 검색으로 찾아오게 콘텐츠를 만들고, 이미지까지 준비하고, 여러 채널에 활용한 뒤 실제 수익 데이터를 보고 다음 콘텐츠를 개선하는 운영 시스템".

- 대상: 1.3.1(`40b1041`) → **1.4.0**. 코드는 가지 `release/1.4.0`.
- **배포 상태: 배포 안 함** (배포는 사용자 승인 뒤 — 아래 '배포 순서').
- 실서버 DB는 분석할 때 읽기만 했고 바꾼 것 없음 (테스트는 모두 로컬 DB·가짜 DB API·모의 서버).

## 1. 분석: 어디서 끊겼나 (실서버 읽기, 2026-10-26)

| 단계 | 실제 상태 |
|---|---|
| 원고 | 14개 — 검수 대기 13 · 발행 준비 1 |
| 게시 | 0개 (예정일이 지난 원고 6개) |
| 다른 채널 | 기록 0 (채널별 버전도 0) |
| 실적·검색어 | 0줄 |
| 수익 모델 | 전부 '미가입' |
| 자동 작가 | 예정일 지난 원고를 세지 않아서, 아무것도 게시하지 않아도 매일 1편씩 새 원고를 더 씀 |

→ '글 만들기'까지만 돌고 게시 → 다른 채널 → 실적 → 개선으로 넘어가지 않음. 1.4.0은 끊긴 곳을 보이게 하고, 자동 작가가 원고만 쌓지 않게 하고, 다음 단계(다른 채널·검색어·개선안)를 기록할 자리를 만듦.

## 5. 남은 한계

- 앱은 블로그 통계·제휴사 실적·유입 검색어를 직접 가져오지 않아 — 붙여넣기·입력·파일만.
- 개선안은 자동 작가(하루 세 번)가 쓰고, 블로그 글은 사용자가 직접 고쳐야 해.
- 추천 규칙의 숫자(조회 100 이상·클릭 30 이상·검색어 3회 이상 등)는 앱이 정한 기준이야.
- 지금 실서버는 원고가 한도(7개)보다 많이(14개) 쌓여 있어서, 배포하면 **검수·게시로 7개 아래가 될 때까지 자동 작가가 새 자동 글을 쓰지 않아** (의도한 동작. 설정에서 한도를 바꿀 수 있음).
