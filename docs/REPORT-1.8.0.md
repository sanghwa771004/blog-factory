## 1. '2,000개 글 학습' 대신 이렇게 한 이유

1. **네이버 블로그는 우리 조사 도구에서 막혀 있어.** 막힌 걸 우회해서 긁지 않았어 (robots·약관을 지킴).
2. **홈판 글 목록이 애초에 없어.** 홈판은 사람마다 다르게 뜨는 개인 피드라서 공통 순위표가 없어 (네이버 2025-09 발표).
3. **2026-09-07부터 네이버 검색 API 약관이 검색 결과를 AI에 넣거나 저장하는 걸 막아** (보도 기준). 공식 창구로 받아도 Claude에 넣으면 위반 소지가 있어.

그래서 네이버 공식 자료·측정 연구·실무자 보고를 근거 강도별로 정리했고, 그 결론을 글공장에 넣었어. 그리고 **'2,000개'는 앞으로 쌓일 우리 글로 대신해** — 글마다 썸네일 변형·제목 길이·7일째 숫자를 기록해서 우리 데이터로 정하게 만들었어 (4번).

조사 결론 한 줄: 네이버는 홈판을 **읽는 사람의 기록**으로 고른다고만 밝혔고, 글쓴이 쪽 공식 기준은 없어. 공식 방향과 실무자 여럿이 겹치는 건 다섯 가지 — 한 주제, 썸네일·제목·본문이 같은 대상, 주제 안 시즌·트렌드 이슈, 첫 3줄에 결론, 직접 써 보고 찍은 것. 글자 수·사진 수·발행 시각·'블로그 지수'는 근거가 없어서 안 쫓아.

## 4. 홈판 기록 · 시험 정리 (DB 022 — 추가형)

- **글마다 '홈판 기록'** (원고 화면 홈판 점검 아래, 게시한 글은 펼쳐져 있음): 누락 확인(확인한 날·검색에 나옴/안 나옴), 7일째 숫자(홈피드 비중 %·검색 비중 %·첫 24시간 조회·7일 조회·평균 사용 시간 '1분 35초'·본 날), 썸네일 변형 A/B/C(썸네일을 앱에서 만들면 저절로), 제목 글자 수(저장할 때 같이), 메모 300자. 모르는 칸은 비워 두면 0이 아니라 '데이터 없음'.
- 숫자는 **네가 블로그 통계에서 보고 적는 것** — 앱·서버가 네이버에서 가져오지 않아. 통계 화면의 정확한 메뉴 이름은 조사로 확인 못 해서 처음 한 번 봐 달라고 화면에 적어 둠.
- **홈 '최근 7일 정리' 아래 '홈판 시험'**: 썸네일 변형별·제목 길이별(25~30자 / 31자 넘게) 글 수·숫자 적은 글 수·홈피드 비중·7일 조회·평균 사용 시간 평균, 누락 건수. 변형마다 **5편 넘게** 숫자가 모여야 '비교' 표시 (보고서의 판정 규칙: 한쪽이 되풀이해 나을 때만 바꿈).
- **AI 브리핑 누적 인용 수**(주 1회, 블로그 프로필에서 본 값): 같은 곳에 적기 → 최근 4번과 늘어난 수.
- **알림** (개선 루프 '데이터 먼저'): 올린 지 1~7일인데 누락 확인 전 → '누락 확인할 때야', 7일 넘었는데 7일째 숫자 없음 → '7일째 숫자를 적을 때야', 게시한 글이 있는데 인용 수를 7일 넘게 안 적음 → '이번 주 AI 브리핑 인용 수를 적을 때야'.
- DB `022_feed_log_1_8_0.sql`: `posts.feed_log jsonb default '{}'`(객체만), `settings.ai_citations jsonb default '[]'`(배열만). 열과 모양 검사만 더하고 데이터는 안 지우고 안 바꿈. 다시 돌려도 같음. 칸 이름·값 검사는 서버가 저장 전에 (`checks.js` feedLogError·citationsError — 알 수 없는 칸·0~100 밖의 비중·음수·소수 조회수·이상한 날짜는 그 칸 이름으로 거절). 022 전 DB면 기록 저장은 'DB 업데이트(022) 필요', 인용 수는 건너뛰고 다른 설정은 저장, 화면은 '022 뒤에 생겨' 안내.

## 6. 내가 정한 것 (네가 따로 정하지 않은 부분 — 보고서도 '우리 기준'이라고 한 숫자)

- 긴 문단 = 150자 넘거나 4문장 넘게 (휴대폰 3~4줄의 근사치).
- '앞 25자 안' = 핵심 낱말이 25번째 글자 안에서 끝남. 핵심 낱말 = 설정의 주력 주제 낱말(제품군) → 없으면 키워드 낱말.
- '장식 사진?' = 사진 설명의 낱말이 그 사진이 든 소제목 부분(소제목부터 다음 소제목 전까지)과 하나도 안 겹침. 낱말로만 보는 거라 ✗가 아니라 △.
- 비교는 변형마다 5편 넘게 (보고서의 '최소 5편'), 평균만 보여주고 '이게 낫다'는 판정은 앱이 안 함.
- 최근 7일 제목 = 같은 채널의 발행 준비·예약·게시 글 (초안끼리는 안 봄 — 하루 10편 초안이 서로 걸리지 않게).
- 메인 블로그 주제 비율 목표 100% (보고서 권고. 70%에서 올림).

## 9. 안 한 것 · 다음 (네가 고르면)

- **관련 글 링크 자리** `[관련 글: …]` (보고서 '시험'): 아직 게시한 글이 0편이라 연결할 글이 없어서 뺐어. 게시 글이 쌓이면 넣을게.
- **데이터 연동** (선택 — 키·약관 확인 필요): 검색광고 키워드도구 API(최근 30일 검색 수 — 쓸모 1순위, 비용 미확인), 데이터랩 검색어 트렌드(API HUB — 지금 한시 무료·유료 전환 예정, 원값 말고 '상승·시즌' 판정만 작가에게), 공공데이터포털 공공서비스(혜택) API(무료·이용 제한 없음). **네이버 검색 결과를 AI에 넣거나 DB에 쌓는 건 안 해** (2026-09 약관).
- '네이버에서 직접 보기' 버튼 + 네 관찰 메모 칸 → 작가에게 메모만 넘기기.
