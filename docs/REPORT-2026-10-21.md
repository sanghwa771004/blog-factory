## 4. 새로 추가한 기능
- **채널과 수익 모델 분리**: 채널 5개, 수익 모델 8개, 조합표(가능/불가/확인 필요 + 이유·근거 주소·확인일). '불가'는 화면·서버·DB 세 곳에서 막음. 설정에서 수익 모델·채널 정보와 판정을 고칠 수 있음
- **수익 모델 정보**: 가입 필요 여부, 링크 필요 여부, 고지 필요 여부·문구·위치, 데이터 출처, 수수료 메모(계산에 안 씀), 내 상태, 확인 안 된 것, 정책 주소·확인일
- **주제 추천**: 검색 의도·독자·문제·제휴 적합도·상품·경쟁·차별화·시즌·확인할 것 + 7가지 점수(근거·출처·신뢰도), 가중치 조절, 채택·보류·제외, '실적 기준 추천'
- **상품 관리**: 모델·가격과 가격 확인일·출처·스펙·장단점·신뢰도·내가 써봄. 확인일 없는 AI 가격은 저장 안 함
- **원고**: 글 유형 11가지, 경험 필요한 유형은 경험 없으면 요청·발행 둘 다 막힘(정보 글은 안 막음), 단계 표시, 발행 전 검사, `[내 경험]` 채우기·빈 칸 지우기, 본문 고치기, 휴지통
- **링크**: 글당 여러 개, 상품·수익 모델 연결, 상태(미확인/정상/오류), 링크별 실적. 링크를 중간 주소로 바꾸지 않음(받은 그대로)
- **채널별 버전**: 쓰레드·인스타·카드뉴스·숏폼 대본·요약·FAQ·제목 후보·블로그별 본문. 원고·출처의 사실만 쓰고 고지문은 앱이 맨 앞에 붙임
- **실적·수익**: 직접 입력, CSV·엑셀 올리기(미리보기, 열 맞추기, 파일 안·이전 파일과 중복 건너뛰기, 잘못된 줄 표시, 올리기 기록, 올리기 취소), 발생·확정·지급·비용·순수익, 클릭률·전환율·1,000회당 수익, 글·채널·수익 모델·카테고리별, 앱이 직접 센 클릭이 없다는 안내
- **추천**: 실적 입력 필요, 조회 대비 클릭 적음, 클릭 대비 구매 적음, 돈이 된 글 후속, 제작 시간 대비 수익, 가격·출처 다시 확인 (근거 숫자와 신뢰도 같이 표시)
- **기기·보안**: 기기별 로그인, 기기 목록·로그아웃, 새 접속 코드 만들기, 백업 내려받기
- **자동 작가**: 하루 세 번, 요청 처리(원고·주제·채널별 버전), 발행표 자동 채우기, 실행 기록, 작업 잠금, 세 번 실패하면 멈춤
- **Claude 안 글공장 버전 5** (이번 마무리 작업): 앱 DB에서 채널·수익 모델·조합·고지문·설정을 불러와 같은 규칙으로 바로 원고 쓰기(`add_post`, 출처 'Claude 안 글공장'), 점수 붙은 주제 추천과 앱 주제함 저장(`add_topics`), 골라서 몰아 쓰기, **앱에서 넣은 요청을 기다리지 않고 바로 처리**(`job_start` → `fill_post`/`add_topics`/`set_variants`/`job_fail` → `log_run`), 앱으로 못 보낸 원고 보관·다시 보내기(이미 들어갔는지 먼저 확인), 미리 검사, 고지문이 없거나 애매하면 복사 막기. 웹 확인이 안 되는 곳이라 상품 비교·장단점 분석·최신 정보 요약은 자동 작가에게 넘기고, 스펙·가격·통계는 쓰지 않음

## 5. 데이터베이스 변경 및 마이그레이션 방법
- 원칙: **표를 지우거나 다시 만들지 않고 더하기만** (`create table if not exists`, `add column if not exists`, 값 갱신은 사용자가 고치지 않은 칸만). 1.1 직전 데이터는 `backup` 스키마에 복사본(004).
- 실서버에는 이미 001~010이 순서대로 적용돼 있어 (Supabase 마이그레이션 기록 10개).
- 새 프로젝트에 처음부터 만들 때: `supabase/migrations/001`~`010`을 번호 순서대로 적용 (Supabase CLI `supabase db push` 또는 대시보드 SQL 편집기에서 차례로 실행). 그다음 Edge Function `blog-app` 배포(`verify_jwt` 끔 — 자체 로그인).
- 확인 방법: `npm test`의 DB 테스트가 PGlite(실제 Postgres 17)에 001~010을 차례로 적용하고 표·함수·RLS·권한을 검사해.
- 되돌리기·복구: `docs/backup-restore.md` (앱 백업 JSON, `backup` 스키마).

## 6. 실행에 필요한 환경변수
`.env.example`에 정리했어. 진짜 값은 저장소에 없고 Supabase 비밀값에만 있어.

| 이름 | 어디 | 설명 |
|---|---|---|
| `SUPABASE_URL` | Edge Function | Supabase가 자동으로 넣어줌 |
| `SUPABASE_SECRET_KEYS` 또는 `SUPABASE_SERVICE_ROLE_KEY` | Edge Function | 서버 키. 자동으로 들어감. 저장소·화면에 없음 |
| `ALLOWED_ORIGINS` | Edge Function (선택) | 앱 주소 허용 목록. 없으면 `https://sanghwa771004.github.io`만 |

앱 화면에는 비밀값이 없어(서버 주소만). 접속 코드는 어디에도 원문이 없고 DB에 SHA-256 해시만 있어.

## 9. 현재 수동으로 진행해야 하는 작업
- 원고 검수: 빈 `[내 경험]` 칸 채우기·지우기, 사실 확인 표시된 문장 확인, 사진 넣기

- 실적 입력 또는 제휴사 리포트 파일 올리기 (주 1회 권장)
- '확인 필요' 정책 직접 확인: 네이버 블로그 제휴 링크 운영정책, 쇼핑 커넥트 고지 문구(비워둬서 지금은 쓰면 오류로 막힘), 쿠팡 단축 주소·금지 사이트 목록, 쓰레드·인스타 유료 파트너십 표시
- 정책 다시 확인: 3~6개월마다 (`docs/policy-research-2026-10-21.md`)
- 한 달에 한 번 백업 내려받기 (무료 요금제라 자동 백업 없음)

## 11. 남아 있는 주요 위험 요소
- **정책 불확실**: 네이버 블로그의 외부 제휴 링크 정책을 공식 문서로 못 확인해서 '쿠팡 × 네이버 블로그'가 '확인 필요'(경고만). 네이버가 막으면 노출 제한 위험
- **AI 내용 오류**: 검사가 써본 척·가격·숫자·과장을 잡지만 모든 틀린 사실을 잡진 못함. 발행 전에 사람이 읽어야 함 (Google도 AI 글은 사람이 확인하라고 안내)
- **비슷한 글 반복**: 자동 채우기를 많이 쓰면 비슷한 글이 쌓일 수 있음 (경고는 뜸). 하루 1~2개 권장
- **예전 방식 로그인**: 1.0 화면용 `x-app-token`(접속 코드 원문) 로그인을 아직 받아줌. 모든 기기가 1.1로 바뀌면 끄는 게 좋음
- **새 로그인 막힘**: 누가 일부러 틀린 코드를 많이 보내면 15분 동안 새 로그인이 막힐 수 있음 (이미 로그인한 기기는 괜찮음)
- **무료 요금제**: 오래 안 쓰면 Supabase 프로젝트가 멈출 수 있고(자동 작가가 다시 켜기 요청), 자동 백업이 없음
- **실제 기기 미확인**: 아이폰 사파리·블로그 에디터 붙여넣기·진짜 리포트 파일·진짜 Claude 화면은 아직 직접 안 눌러봄
- **Claude 안 글공장**: 지금은 나만 열 수 있어. 링크를 남과 공유하면 그 사람도 이 페이지 보관함(원고 사본)은 볼 수 있으니 공유하지 마. 앱 DB는 그 사람의 Supabase 계정으로는 열리지 않아
