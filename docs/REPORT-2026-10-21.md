## 4. 새로 추가한 기능
- **채널과 수익 모델 분리**: 채널 5개, 수익 모델 8개, 조합표(가능/불가/확인 필요 + 이유·근거 주소·확인일). '불가'는 화면·서버·DB 세 곳에서 막음. 설정에서 수익 모델·채널 정보와 판정을 고칠 수 있음
- **수익 모델 정보**: 가입 필요 여부, 링크 필요 여부, 고지 필요 여부·문구·위치, 데이터 출처, 수수료 메모(계산에 안 씀), 내 상태, 확인 안 된 것, 정책 주소·확인일
- **주제 추천**: 검색 의도·독자·문제·제휴 적합도·상품·경쟁·차별화·시즌·확인할 것 + 7가지 점수(근거·출처·신뢰도), 가중치 조절, 채택·보류·제외, '실적 기준 추천'
- **상품 관리**: 모델·가격과 가격 확인일·출처·스펙·장단점·신뢰도·내가 써봄. 확인일 없는 AI 가격은 저장 안 함
- **원고**: 글 유형 11가지, 경험 필요한 유형은 경험 없으면 요청·발행 둘 다 막힘(정보 글은 안 막음), 단계 표시, 발행 전 검사, `[내 경험]` 채우기·빈 칸 지우기, 본문 고치기, 휴지통
- **링크**: 글당 여러 개, 상품·수익 모델 연결, 상태(미확인/정상/오류), 링크별 실적. 링크를 중간 주소로 바꾸지 않음(받은 그대로)
- **채널별 버전**: 쓰레드·인스타·카드뉴스·숏폼 대본·요약·FAQ·제목 후보·블로그별 본문. 원고·출처의 사실만 쓰고 고지문은 앱이 맨 앞에 붙임
- **실적·수익**: 직접 입력, CSV·엑셀 올리기(미리보기, 열 맞추기, 파일 안·이전 파일과 중복 건너뛰기, 잘못된 줄 표시, 올리기 기록, 올리기 취소), 발생·확정·지급·비용·순수익, 클릭률·전환율·1,000회당 수익, 글·채널·수익 모델·카테고리별, 앱이 직접 센 클릭이 없다는 안내
- **추천**: 실적 입력 필요, 조회 대비 클릭 적음, 클릭 대비 구매 적음, 돈이 된 글 후속, 제작 시간 대비 수익, 가격·출처 다시 확인 (근거 숫자와 신뢰도 같이 표시)
- **기기·보안**: 기기별 로그인, 기기 목록·로그아웃, 새 접속 코드 만들기, 백업 내려받기
- **자동 작가**: 하루 세 번, 요청 처리(원고·주제·채널별 버전), 발행표 자동 채우기, 실행 기록, 작업 잠금, 세 번 실패하면 멈춤
- **Claude 안 글공장**: 앱 DB에서 채널·수익 모델·조합·고지문·설정을 불러와 같은 규칙으로 바로 원고 쓰기(`add_post`, 출처 'Claude 안 글공장'), 점수 붙은 주제 추천과 앱 주제함 저장(`add_topics`), 골라서 몰아 쓰기, **앱에서 넣은 요청을 기다리지 않고 바로 처리**(`job_start` → `fill_post`/`add_topics`/`set_variants`/`job_fail` → `log_run`), 앱으로 못 보낸 원고 보관·다시 보내기(이미 들어갔는지 먼저 확인), 미리 검사, 고지문이 없거나 애매하면 복사 막기. 웹 확인이 안 되는 곳이라 상품 비교·장단점 분석·최신 정보 요약은 자동 작가에게 넘기고, 스펙·가격·통계는 쓰지 않음
- **1.1.2에서 바뀐 동작**
  - 고지문이 비었거나 애매한 수익 모델 글은 앱에서도 **복사 자체가 막힘** (네이버 쇼핑 커넥트·CPA는 공식 문구를 확인 못 해서 일부러 비워둠 → 문구를 넣기 전까지 복사 안 됨)
  - 실적 파일: 같은 수익 모델·채널·글(연결 안 된 줄은 글 이름)·기간이면 같은 줄. 같은 파일 안 상품·주문별 줄은 더해서 한 줄(모든 칸이 똑같은 줄만 '파일 안 중복'으로 뺌), 예전과 숫자가 같으면 중복, **다르면 새 숫자로 바꾸고 예전 숫자는 보관** → 올리기 취소하면 그 파일이 고친 줄은 예전 숫자로 돌아감
  - 예약·게시 완료로 갈 때도 서버가 다시 검사, 설정(수익 모델·채널·조합표·상품)을 바꾸면 그걸 쓰는 준비된 원고를 다시 검사해서 걸리면 '검수 필요'로 되돌리고 알림
  - 30분 넘게 멈춘 작업 취소, 지웠다 되살린 원고 → '작업 실패' → '다시 요청' 가능
  - 자동 작가·Claude 안 글공장은 이미 원고가 있는 주제로 원고를 또 만들지 않음 (DB `add_post`가 거부). 앱에서 직접 요청하는 건 막지 않아 — 같은 주제를 다른 채널 글로 쓸 수도 있어서. 대신 앱은 '제작 요청됨' 주제를 요청 목록에 안 보여줌

## 5. 데이터베이스 변경 및 마이그레이션 방법
- 원칙: **표를 지우거나 다시 만들지 않고 더하기만** (`create table if not exists`, `add column if not exists`, `create or replace function`, 값 갱신은 사용자가 고치지 않은 칸만). 1.1 직전 데이터는 `backup` 스키마에 복사본(004).
- 실서버에는 001~011이 순서대로 적용돼 있어 (Supabase 마이그레이션 기록 11개, 011 = `review_fixes`). 011 적용 전에 실적·올린 파일 기록이 0줄이라 바뀐 실적 기준으로 옮길 예전 데이터는 없었어.
- 011이 더한 것: `metrics.id_key`(같은 줄 열쇠, 열쇠가 있는 줄끼리만 겹치지 않게 하는 인덱스), `metrics.replaced`(고치기 전 숫자 기록), `imports.rows_changed`(고친 줄 수). 함수 9개를 같은 이름·같은 받는 값으로 바꿈, 외부 역할 실행 권한 회수.
- 새 프로젝트에 처음부터 만들 때: `supabase/migrations/001`~`011`을 번호 순서대로 적용 (Supabase CLI `supabase db push` 또는 대시보드 SQL 편집기에서 차례로 실행). 그다음 Edge Function `blog-app` 배포(`verify_jwt` 끔 — 자체 로그인).
- 확인 방법: `npm test`의 DB 테스트가 PGlite(실제 Postgres 17)에 001~011을 차례로 적용하고 표·함수·RLS·권한을 검사해. 실서버에서도 011 적용 뒤 같은 동작을 되돌림(롤백) 트랜잭션 안에서 확인했어 (7장).
- 되돌리기·복구: `docs/backup-restore.md` (앱 백업 JSON, `backup` 스키마).

## 11. 남아 있는 주요 위험 요소
- **정책 불확실**: 네이버 블로그의 외부 제휴 링크 정책을 공식 문서로 못 확인해서 '쿠팡 × 네이버 블로그'가 '확인 필요'(경고만). 네이버가 막으면 노출 제한 위험
- **AI 내용 오류**: 검사가 써본 척·가격·숫자·과장을 잡지만 모든 틀린 사실을 잡진 못함. 발행 전에 사람이 읽어야 함 (Google도 AI 글은 사람이 확인하라고 안내). 1.1.2에서 안내 문장은 써본 척에서 뺐기 때문에, '써보세요'처럼 안내하는 척 경험을 꾸민 문장은 사람이 봐야 함
- **비슷한 글 반복**: 자동 채우기를 많이 쓰면 비슷한 글이 쌓일 수 있음 (경고는 뜸). 하루 1~2개 권장
- **실적 줄 합치기**: 같은 글·같은 기간의 줄은 하나로 합쳐 저장돼서, 한 리포트 안에서 링크별로 나뉜 숫자는 링크별로 따로 남지 않아 (링크별로 보려면 링크 실적 직접 입력). 리포트에 글 이름이 없어 '글 연결 안 됨'으로 들어간 줄은 그 이름 글자로 같은 줄을 판단해
- **예전 방식 로그인**: 1.0 화면용 `x-app-token`(접속 코드 원문) 로그인을 아직 받아줌. 1.1.2부터 이 방식으로는 '발행 완료'를 못 바꾸지만, 모든 기기가 1.1로 바뀌면 아예 끄는 게 좋음
- **새 로그인 막힘**: 누가 일부러 틀린 코드를 많이 보내면 15분 동안 새 로그인이 막힐 수 있음 (이미 로그인한 기기는 괜찮음)
- **무료 요금제**: 오래 안 쓰면 Supabase 프로젝트가 멈출 수 있고(자동 작가가 다시 켜기 요청), 자동 백업이 없음
- **실제 기기 미확인**: 아이폰 사파리·블로그 에디터 붙여넣기·진짜 리포트 파일·진짜 Claude 화면은 아직 직접 안 눌러봄
- **Claude 안 글공장**: 지금은 나만 열 수 있어. 링크를 남과 공유하면 그 사람도 이 페이지 보관함(원고 사본)은 볼 수 있으니 공유하지 마. 앱 DB는 그 사람의 Supabase 계정으로는 열리지 않아
- **남은 점검 흔적**: 1.1.1 실서버 점검 세션 1개('[테스트] 실서버 점검 2')는 로그아웃만 된 채 행이 남아 있어 (이 세션으로는 아무것도 못 함). 예약 작업 수동 실행 기록이 실행 기록에 2줄 남아 있어. 1.0.0 태그(`v1.0.0`) 올리기는 실패했고 같은 내용이 원격 가지 `backup/v1.0.0`에 있어

## 12. 다음 개발 단계
