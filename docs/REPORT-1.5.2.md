**018 끝부분 (아직 안 들어간 4줄)** — Supabase SQL Editor 에서 실행 (DB가 사람 확인을 요구하는 부분이라 Claude가 대신 못 돌림):
```sql
begin;
alter table public.post_images drop constraint post_images_kind_check;
alter table public.post_images add constraint post_images_kind_check check (kind in ('ai', 'stock', 'upload', 'card', 'composite'));
alter table public.post_images drop constraint post_images_provider_check;
alter table public.post_images add constraint post_images_provider_check check (provider in ('', 'openai', 'cloudflare', 'gemini', 'pexels', 'upload', 'cardnews', 'composite'));
commit;
```
- 넓히기만 해서 지금 있는 줄은 모두 그대로 통과해 (데이터를 바꾸지 않음). `018_product_scene_1_5_1.sql` 맨 끝 '5' 구역과 같은 내용.
- **실행 뒤 확인** (읽기만): 
```sql
select conname, pg_get_constraintdef(oid) from pg_constraint where conname in ('post_images_kind_check', 'post_images_provider_check');
```
  두 줄 모두 `'composite'` 가 들어 있으면 끝. 'Success' 가 아니면 아무것도 바뀌지 않은 거야 (begin … commit 이라 반쯤 바뀌지 않음).

**019 (1.5.2 새 마이그레이션 — 색인 하나만)**: `supabase/migrations/019_composite_once_1_5_2.sql`. 같은 합성이 두 줄로 저장되지 않게(같은 요청이 거의 동시에 두 번 올 때) '저장 경로가 같은 살아 있는 합성은 한 줄'인 고유 색인을 더해. 데이터를 바꾸거나 지우지 않고, 다시 돌려도 같아. 018 끝부분과 순서 상관없음. 이미 같은 경로의 합성이 두 줄 있으면(지금은 합성 0장) 색인을 만들지 않고 알림만 남겨.
- 실행 뒤 확인 (읽기만): `select indexname, indexdef from pg_indexes where indexname = 'post_images_composite_path_uniq';` → 한 줄이면 끝.
- 019 를 안 넣어도 1.5.2 서버는 돌아가 (그때는 아주 드문 동시 요청에서 두 줄이 생길 수 있는 예전 상태).

## 2. 만든 것 (지시서 항목별)
**P0 배포 상태** — 위 1번 표. 018 끝부분 SQL·확인 절차·배포 순서.

**P1 작업 이어 하기 (6번)** — `jobstore.js`(새 파일), `product.js`
- 진행 상황을 **이 기기 브라우저 IndexedDB(`gf-jobs`)** 에만 저장 (localStorage 안 씀, 서버 표 안 늘림). 상품 이미지·추가 사진·마스크·배경 후보·고른 후보·합성 결과의 **이미지 ID**, 방식·목적·장면·각도·자리·빛·색·밝기·비율·모델·품질·장수·위치·크기·그림자·밝기·색온도, 끝내 저장 못 한 합성의 요청 번호.
- 서버에 아직 저장 안 한(손으로 고친) 마스크만 PNG Blob으로 (작음). 사진 파일·**서명 주소**·접속 코드·세션·키는 저장하지 않음 — 저장 직전에 알 수 없는 칸을 모두 버리는 `cleanJob` 으로 거름.
- 다시 열면 '하던 작업이 있어 — 이어서 작업하기 / 새로 시작하기'. 이어 하기는 이미지를 ID로 다시 불러 **새 서명 주소**를 받음 (지운 이미지는 빼고 알려줌).
- 보존: 마지막으로 고친 뒤 14일, 끝낸 작업 3일, 최대 8개 · 로그아웃하면 DB 통째로 지움. Safari 7일 규칙은 안내.
- 저장 공간 부족(QuotaExceeded)·저장소 없음(사생활 보호 모드)·남은 공간 15MB 미만(`navigator.storage.estimate`, Safari 17+)이면 화면 위에 알림 — 작업은 계속.
- 화면을 내리거나(`visibilitychange`) 페이지를 떠날 때(`pagehide`) 바로 저장.

**P1 아이폰 Safari·배경 지우기 안정성 (4·5번)** — `cutout.js`, `seg-worker.js`(새 파일), `product.js`
- 배경 지우기를 **모듈 Web Worker** 에서 (Safari 15+). 화면 쪽에서 모델 파일·실행기를 받아 SHA-256 을 확인하고 Cache Storage(`gf-cutout-v1`)에 둔 뒤 일꾼에 넘김. 일꾼이 안 되면 화면 쪽으로 (그렇다고 알림).
- 진행률(받기 n/19MB → 준비 → 처리 + 초) · **취소**(일꾼을 끝냄 — 계산 중에도 바로 멈춤) · 시간 제한 90초(정밀 150초) · 끝나고 45초 안 쓰면/화면을 내리면/합성 저장 전에 도구를 메모리에서 내림.
- 기기 확인: WebAssembly SIMD(실행기 필수, iOS 16.4+) · Worker · Cache · IndexedDB · `deviceMemory`(크롬 계열만). **간단 모드**(사진 1,600·영역 1,024·미리보기 600px): SIMD 없음·메모리 2GB 이하·처리 중 페이지가 꺼졌다 다시 열림(아이폰 메모리 부족 흔적)·시간 초과 때 자동, 사용자가 직접 켜고 끌 수 있음. 코어 수는 기준으로 안 씀.
- 캔버스 메모리가 모자라 그리기가 실패하면 원본을 건드리지 않고 알림 → 간단 모드 권함.
- 무거운 처리는 일꾼으로 뺐지만 **합성 저장(원래 크기로 다시 그리기)은 아직 화면 쪽**이야 (복사본을 넘기면 아이폰에서 메모리가 두 배가 돼서) — 1~3초 멈출 수 있어. '저장할 그림을 만드는 중…'을 먼저 보여줌.

**P1 배경 제거 품질 (4번)** — `cutout.js`, `product.js`
- U²-Netp 는 빠른 기본 그대로. **정밀하게(2단계)**: 상품 상자(+상자 긴 변의 12%)만 잘라 한 번 더 — 새 파일 없이 같은 모델. **두 결과가 상자 안에서 90% 넘게 겹칠 때만** 2단계를 쓰고, 덜 겹치면(다른 물건을 잡음) 처음 결과를 그대로 두고 알려줌. 값은 비교 시험(5번)에서 고른 그대로이고, 옮긴 코드가 시험 코드와 같은 결과인 걸 확인했어.
- **간단히(모델 없이) 고침**: 예전엔 옆 칸끼리만 비교해서 부드러운 윤곽 틈으로 상품 안까지 번졌어(비교 시험에서 24장 중 20장이 거의 0). 테두리의 배경 색을 기억하고 천천히만 따라가게 바꿈 — 단색 배경 합성 8장 IoU 0.13 → 0.64 (5번).
- **영역 품질 점수(추정)**: 덮인 넓이·떨어진 조각·가장자리에 닿음·흐릿한 띠 두께·**경계가 사진 윤곽 위에 있는 비율**·안쪽 구멍 → 좋아 보임/확인 필요/고쳐야 함 + 이유. 정답 없이 보는 값이라고 화면에 씀.

- 무손실 최적화: 불투명 캔버스로 PNG (투명도 칸 없이 — 브라우저에 따라 작아짐). 픽셀은 같음 (화면 시험이 상품 칸을 원본과 비교).
- XMLHttpRequest 로 올리는 진행률 %. 실패 이유(인터넷 끊김·시간 초과·저장소 실패·저장 공간·DB 업데이트 필요…)와 **'다시 저장 (같은 요청)'**.
- 서버: 화면이 보낸 **요청 번호로 경로를 정함** → 같은 번호로 다시 오면 이미 저장된 그 이미지를 돌려줌, 파일만 올라가고 기록이 안 됐으면 같은 경로에 덮어씀. 같은 번호가 거의 동시에 두 번 와도(응답을 못 받고 바로 다시 저장) **019 고유 색인**이 두 번째 기록을 막고 서버는 먼저 저장된 줄을 돌려줌 — 그 파일은 지우지 않음. 기록이 실패하면 올린 그 파일만 지움 (같은 경로를 가리키는 기록이 생겼으면 그대로 둠).
- **실패한 합성 파일만 정리**: 새 길 `POST images/composite/cleanup` — 'composite/' 아래, 그 요청 번호 이름, 어떤 이미지 기록도 가리키지 않고 **올린 지 15분이 넘은** 파일만 지움 (아직 저장 중인 요청의 파일을 지우지 않게). 새 파일은 번호를 기억해 두고 다음에 다시 — 화면은 '그만두기'·다음 저장 성공·이어 하기·'새로 시작하기' 때 부름. 원본 상품·배경·마스크는 경로가 달라서 못 지움. 그래서 실패한 파일이 몇 분~며칠 남아 있을 수 있어 (보관함 용량에만 영향).

## 7. 실제 API 생성 시험 — 안 함
이번 지시서가 '이 요청만으로 실제 이미지 생성·유료 API 호출을 하지 마라'라서, 무료 Cloudflare 포함 **실제 이미지 생성은 한 번도 안 했어.** 그래서 **실제 이미지 품질(자연스러움·외형 보존·조명 등)은 확인하지 않았어.** 공급자 비교 화면과 서버 길은 모의 서버로만 확인했어. 승인해 주면 순서: ① 무료 Cloudflare 빈 배경 2장 → 원본 보존 합성 → ② 무료 Cloudflare 실사 장면 → (키 + 따로 승인) ③ Sunburst ④ Gemini — 같은 상품·장면으로, 공급자 비교 화면에서.

## 8. 아이폰 Safari — 미검증
실제 아이폰 Safari 에서는 **돌려 보지 않았어** (이 작업 환경에서 아이폰을 쓸 수 없음). 확인한 건: 휴대폰 크기 Chromium 화면 시험(일꾼·취소·이어 하기 포함), 공식 문서상 지원 버전(2번), 앱의 크기 한도가 캔버스 한도 안이라는 것. 배포 뒤 아이폰에서 볼 것: 처음 도구 받기(19MB)·배경 지우기·취소·다른 앱 갔다 오기·새로고침 뒤 이어 하기·합성 저장(진행률)·간단 모드.

## 9. 남은 문제와 다음 버전 우선순위
1. 018 끝부분 실행 → 019 → 1.5.1·1.5.2 배포 (지금 실서버에 원본 보존 합성 결과를 저장할 수 없음)

6. 합성 저장 그리기도 일꾼으로 (아이폰에서 1~3초 멈춤 없애기 — 메모리 두 배 문제를 풀어야 함)
