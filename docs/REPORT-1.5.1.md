# 글공장 1.5.1 상품 사진으로 장면 만들기 — 보고서 (2026-10-28)

목표(사용자 지시서 1.5.1 "상품 이미지 기반 장면 제작 및 원본 보존 합성"): 상품 사진 하나를 올리면 **제품을 정확하게 보존하는 합성(모드 A)** 과 **자연스러운 연출을 위한 AI 생성(모드 B)** 을 목적에 맞게 골라 블로그 본문·대표·상품 상세·SNS·광고 이미지를 만들 수 있게.

- 대상: 1.5.0(`0fab3d3`, 실서비스) → **1.5.1**. 코드는 가지 `release/1.5.1`. 1.5.0 배포 뒤 찾은 '백업에 AI 검수·내 평가' 고침(`479e51b`, 아직 안 올림)도 이 가지에 들어 있어.
- **배포 상태: 아직 안 함 (승인 필요).** DB 018·서버·앱 화면·예약 작업 프롬프트·Claude 안 글공장 전부 그대로 1.5.0이야. 순서는 10번.
- **유료 API는 한 번도 부르지 않았어.** 모든 테스트는 가짜 공급자·가짜 DB API·로컬 DB(PGlite)·모의 서버로 돌렸어. 배경 지우기 모델(U²-Netp)만 **진짜로** 돌렸어 — 외부 API가 아니라 앱 안에 들어 있는 모델이라 돈이 안 들고, 화면 테스트의 브라우저(Chromium) 안에서 실제로 실행했어. 실서비스 DB·서버·예약 작업은 이번 작업에서 바꾸지 않았어.
- **상품 원본 보존 합성은 실제로 구현했어** (메타데이터만이 아니라 픽셀 레이어 합성 — 2번). 원본 크기 그대로 얹으면 상품 안쪽 칸이 원본 사진 픽셀과 한 칸도 안 다른 것을 실제 브라우저에서 확인했어 (6번). 다만 **실제 AI 배경·실제 아이폰으로는 아직 안 해 봤어** (7번).

## 2. 원본 보존 합성의 실제 구현 방식

**어디서 하나 — 이 기기(브라우저).** 서버(Supabase Edge Function)는 요청마다 CPU 2초·메모리 256MB 한도이고 sharp·libvips 같은 이미지 도구를 못 써 (Supabase 'Edge Functions limits', 2026-10-28 확인). 외부 배경 지우기 API는 유료이거나(무료로 확인되지 않음), Cloudflare Images의 `segment=foreground`처럼 따로 도메인·Images 구독이 필요해. 그래서 배경 지우기와 합성은 모두 브라우저에서 하고, 서버는 결과 PNG를 검사·저장·기록만 해.

| 단계 | 하는 일 (파일) |
|---|---|
| 1. 상품 사진 읽기 | 보관함의 원본 파일을 1시간짜리 서명 주소로 받아 그대로 읽음 (긴 변 2,560px까지 — 앱으로 올린 사진은 올릴 때 이미 2,560px 안이라 줄지 않음. 더 크면 줄여 읽었다고 화면에 밝힘). 원본 파일·기록은 고치지 않음 (`cutout.js` `decodeImage`) |
| 2. 배경 지우기 | U²-Netp(4.6MB, Apache-2.0)를 ONNX Runtime Web 1.30.0(MIT, WebAssembly)으로 실행: 320×320 입력(ImageNet 평균·표준편차) → 확률 지도 → 사진 크기(긴 변 1,600px 이하)로 늘림 → 유도 필터로 실제 경계에 맞춤 → 부드러운 문턱 → 작은 조각 지우기·구멍 메우기. 처음 한 번 모델·실행기(약 19MB)를 앱 주소(GitHub Pages)에서 받아 이 기기 Cache Storage에 두고, SHA-256으로 확인 (다르면 안 씀). 안 되면 '간단히'(테두리 색). 원래 투명한 PNG면 그 투명도 (`autoMask`·`mapToMask`·`keepMain`·`simpleMask`) |
| 3. 마스크 고치기·저장 | 칠하기(남기기·지우기), 붓 크기, 되돌리기, 저장 → 흰색+투명도 PNG로 `POST /images/{id}/mask` (서버: PNG만, 6MB·4096px까지, 상품 사진과 같은 비율·크기 이하, 진짜 사진(쓸 권한 확인한 직접 올림·Pexels)에만, `mask/…` 경로, 방법·고침 여부·덮은 비율·비용 0원 '청구 없음' 기록) |
| 4. AI 배경 | 상품 사진은 보내지 않고 지시문만: 상품을 그리지 말 것, 상품이 놓일 자리(가운데·왼쪽·오른쪽)를 비우고 같은 카메라 각도(정면·살짝 위·바로 위)·바닥, 글자·로고 없음, 목적별 빛·구도 (`LAYER_BG_RULES`). 기록은 `preset` `pscene_layer` + 원본 상품 id, 사진 자리 후보로는 안 보임 |
| 5. 합성 | 배경을 고른 비율로 가운데 맞춰 자르고(cover) 결과 크기로(줄일 때 면적 평균). 상품 상자(마스크 경계) → 위치·크기·회전. **배율 1(원본 크기 그대로)·회전 0이면 원본 칸을 가장 가까운 칸 그대로 복사** — 다시 계산하지 않음. 그 밖은 원본에서 크기만 다시 뽑음(AI가 다시 그리지 않음): 줄일 때는 먼저 면적 평균으로 그 크기까지 줄이고(투명도로 곱한 색으로 — 가장자리에 원래 배경색이 번지지 않게) 거의 1:1로 쌍선형, 늘릴 때는 쌍선형. 가장자리(반투명 칸)만 원래 배경색이 묻어나지 않게 안쪽 색 쪽으로 정리, 불투명 칸은 그대로. 그림자 = 상품 윤곽을 바닥 쪽으로 눌러 빛 방향으로 기울인 그림자 + 바닥에 닿는 곳의 좁고 진한 접촉 그림자, 상자 흐림 2번. 밝기·색온도는 상품·배경 따로, 둘 다 0이 기본(바꾸지 않음) (`composite`·`render`) |
| 6. 저장 | 미리보기는 줄인 사본으로(움직일 때 수십 ms), 저장은 원래 크기로 다시 그려 PNG(다시 압축 안 함) → `POST /images/composite` (서버: 이미지 파일 검사·4096px·12MB, 숨은 정보 지우기, `composite/…`, 원본 상품·배경·마스크가 맞는지·레이어 설정을 DB 함수가 다시 확인, 실패하면 올린 합성 파일만 지움). 누를 때의 설정(위치·비율·마스크)으로 저장하고, 다시 저장하면 또 새 이미지 |
| 7. 기록 | `post_images`(종류 `composite`, 공급자 `composite`, `composite_mode` `layer`, `product_image_id`·`background_image_id`·`mask_id`·`layer`·`product_check`, 출처·라이선스는 상품 사진에서) + `product_masks` + 배경의 `image_generations`. 미리보기·보관함에 원본 상품 사진·AI 배경·합성 설정·마스크·비용(모델 · 배경 지우기 따로) |

결과 크기: 고른 비율, 긴 변 = 목적 크기(본문·대표·광고 1,600 · 상품 상세 1,200 · SNS 1,080)와 배경 해상도 × 1.25 중 작은 쪽. 늘리면 '흐려 보일 수 있어', 밖으로 나가면 '조금 나갔어' 알림.

## 3. 바뀐 파일과 이유

## 7. 실제 API 이미지 품질 비교 — 안 함 (사유)

- **실제 생성 API는 한 번도 안 불렀어.** 이유: (1) 1.5.1은 아직 실서버에 안 올렸어 — 새 생성 흐름은 배포 뒤에만 실제 공급자로 갈 수 있어. (2) 서버 Secrets에 OpenAI·Gemini 키가 없어 (1.5.0 배포 때 확인). (3) 유료 생성은 사용자 승인이 있어야 해 (지시서·작업 규칙). (4) 작업 환경에서는 공급자 주소로 나갈 수 없어서 테스트 서버도 127.0.0.1 말고는 못 나가게 띄웠어.
- 그래서 **'실제 이미지 품질'은 검증 안 됨**이야. 화면 테스트의 배경 이미지는 미리 넣어 둔 시험 사진이고, 거기서 확인한 건 '상품 칸이 원본 픽셀 그대로인지·자리·비율·실패 처리' 같은 **계산과 흐름**이지 AI 배경의 품질이 아니야.
- 배포 뒤 해볼 수 있는 순서 (돈 안 드는 것부터): ① 무료 Cloudflare FLUX.2 klein으로 모드 A 배경 2장 → 실제 상품 사진으로 합성·저장·검수 (0원) ② 같은 상품으로 모드 B 1장 (무료 — 참고 사진 500px 사본이라 디테일은 기대하지 않기) ③ (승인 뒤, 유료) OpenAI 키를 넣고 Sunburst 높음으로 모드 A·B 한 장씩 — 예상 약 $0.044 + $0.056.

## 9. 해결하지 못한 문제와 후속 작업

- **실제 아이폰 Safari에서 배경 지우기(WebAssembly 약 19MB)·합성을 안 돌려 봤어** (검증 안 됨). 테스트는 Chromium(휴대폰 크기)에서만. Safari 메모리가 모자라면 '간단히'로 바뀌어야 하는데 그 경로도 실제 기기로는 못 봤어.
- **실제 AI 배경과 상품의 어울림(빛 방향·원근·바닥 높이)** 은 그림자·밝기·위치 조절로 사람이 맞추는 방식이야. 자동으로 빛을 맞추지는 않아.
- U²-Netp는 작은 모델(320×320)이라 머리카락·투명한 물건·배경과 색이 비슷한 상품은 경계가 거칠 수 있어 → 칠해서 고치기로. 더 정확한 모델(예: 큰 분할 모델)은 받는 크기가 커서 이번엔 안 넣음.
- 크기를 바꾸거나 돌리면 상품 칸은 원본에서 다시 뽑은 값이라 '원본 픽셀 그대로'가 아니야 (AI가 다시 그리는 건 아님). 정확히 원본 그대로는 '원본 크기 그대로' + 회전 0일 때만 — 화면에 그렇게 적어 둠.
- 화면을 새로 고치면 진행 중인 단계(고친 마스크·후보·위치)가 사라져. 저장한 마스크·배경·합성은 보관함에 남고, '상품 장면 화면에서 이어 하기'로 결과부터 다시 열 수 있어.
- Brave 같은 브라우저는 캔버스 값을 일부러 흔들어(지문 방지) 합성 결과가 아주 조금 달라질 수 있어 (확인 안 함).
- Gemini `generateContent`가 '(Legacy)'가 됨 — 지금은 완전히 지원되지만, 새 Gemini 이미지 모델이 Interactions API로만 나오면 어댑터를 더해야 해 (후속).
- 실서비스에 OpenAI·Gemini 키가 없어서 고품질 모드(Sunburst)는 '키 없음'으로 잠겨 보여. 쓰려면 사용자가 Secrets에 키를 넣어야 해.
- 예전(1.5.0)에 '진짜 제품 사진 참고'로 만든 AI 합성 이미지는 상품 장면으로 보지 않아서 검수 없이도 예전처럼 쓸 수 있어 (새 규칙을 소급하지 않음 — 원하면 그 이미지들도 검수 대상으로 바꿀 수 있어).
- 1.5.0 때 찾은 '백업에 AI 검수·내 평가' 고침도 이번 배포에 같이 올라가.
- 버튼을 동시에 두 번 누르는 경우·영역을 저장하는 동안 칠하는 경우는 코드로 막았지만 자동 시험은 없어 (사람이 해 보거나 다음에 시험을 더해야 함).
- 1.5.0 화면이 같이 저장한 고품질 모드 기본값(Flare · 높음)은 이제 새 기본값(Sunburst · 높음)으로 바뀌어 보여 — 실서비스 설정에 그렇게 저장돼 있는지는 이번에 안 봤어 (배포 전 점검에서 읽기만으로 확인할 것). 일부러 Flare · 높음을 쓰고 싶었다면 설정에서 골라서 저장해야 해.
