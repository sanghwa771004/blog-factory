# 운영 시스템 안내 (1.4.0)

글공장은 AI로 글을 많이 만드는 앱이 아니라, **사람들이 검색으로 찾아오게 글을 만들고 → 이미지까지 준비하고 → 여러 채널에 쓰고 → 실제 숫자를 보고 → 다음 글을 고치는** 운영 도구야. 1.4.0은 이 흐름이 끊기는 곳을 보이게 하고, 끊긴 곳에서 바로 할 일 하나를 알려주는 데 집중했어.

## 홈 맨 위 '운영 흐름'

| 칸 | 세는 것 | 어디서 오는 숫자 |
|---|---|---|
| 주제 | 후보·채택 주제 | 주제 탭 |
| 원고 | 자동 작가가 쓰는 중이거나 검수할 원고 | 콘텐츠 |
| 게시 준비 | 발행 준비 완료·예약 | 콘텐츠 |
| 게시 | 게시 완료로 기록한 글 (최근 7일 몇 개인지 같이) | '게시 완료 기록' |
| 다른 채널 | 게시한 글 중 다른 채널(티스토리·쓰레드·인스타 등)에도 올렸다고 기록한 글 (켜 둔 다른 채널이 없는 글은 빼고) | 원고의 '다른 채널에 올리기' |
| 실적 | 게시한 지 7일 지난 글 중 실적을 한 줄이라도 넣은 글 | 실적 입력·파일 올리기 |
| 개선 | 개선안이 있는 글 (고칠 것 몇 개인지 같이) | 원고의 '개선안' |

**지금 막힌 곳**은 아래 순서로 처음 걸리는 하나만 보여줘. 막힌 곳을 풀면 다음 단계가 보여. 서버가 기록을 못 읽었으면(DB 업데이트 전이거나 잠깐 오류) 그 칸은 0이 아니라 '데이터 없음'(–)으로 두고, 그걸로 막힌 곳을 고르지 않아.

1. **게시** — 검수·게시 안 한 원고가 한도만큼 쌓였거나, 원고는 있는데 게시한 글이 하나도 없을 때
2. **다른 채널** — 게시한 글 중 다른 채널에 올린 글이 절반이 안 될 때 (켜 둔 다른 채널이 없으면 건너뜀 — 설정 > 게시 채널)
3. **실적** — 게시한 지 7일 지난 글에 실적이 안 들어왔을 때
4. **개선** — 실적·검색어로 보면 고칠 글이 있을 때
5. **주제** — 위가 다 됐는데 다음에 쓸 원고·주제가 없을 때

그 아래에 **예정일이 지난 원고**가 있으면 '날짜 다시 잡기'(내일부터 빈 날로, 하루 발행 수 그대로, 단계는 그대로), **'사용 중'인 수익 모델이 없으면** 그 사실을 같이 보여줘. 수익 모델이 전부 '미가입'이면 게시해도 수익이 잡히지 않아.

'예약'으로 둔 원고는 날짜 다시 잡기로 옮기지 않아 — 예약한 날이 지났으면 블로그에 이미 올라갔을 수 있어서. 대신 '예약한 날이 지난 원고 n개'로 따로 알려주니, 올라갔으면 '게시 완료 기록'을, 안 올라갔으면 원고에서 발행일을 바꿔줘.

## 쌓아둘 원고 한도 (자동 작가 속도 조절)

- 검수·게시 안 한 원고(검수 필요·정보 필요·발행 준비·예약)가 **한도만큼 쌓이면 자동 작가가 새 자동 글을 멈춰.** 앱에서 직접 요청한 원고와 Claude 안 글공장에서 쓴 원고는 그대로 써.
- 한도는 설정 > 자동 글쓰기 > '쌓아둘 원고 한도'. 기본(자동)은 **하루 발행 수 × 7** (하루 1편이면 7개).
- DB(`add_post`)도 같은 규칙으로 자동 글 저장을 거절해서, 자동 작가가 규칙을 놓쳐도 원고가 더 쌓이지 않아.
- 기다리는 요청 원고는 다음 실행에 먼저 채워져서 쌓인 원고가 돼. 그래서 자동 글 수는 '한도 − 쌓인 원고 − 기다리는 요청 원고'까지야 (홈 '자동 작가' 칸도 이렇게 계산해).
- 예전에는 예정일이 지난 원고를 세지 않아서, 아무것도 게시하지 않아도 자동 작가가 매일 새 원고를 하나씩 더 썼어. 1.4.0부터는 안 그래.

## 한 편의 흐름 (원고 화면)

1. **검수 → 발행 준비 완료 → 게시 완료 기록** (지금처럼). 앱은 대신 올리지 않아.
2. **다른 채널에 올리기**: 채널별 버전(쓰레드·인스타·티스토리용 등)을 복사해서 직접 올리고 '올렸어 — 기록'. 주소는 https만 받고, 모르면 비워도 돼.
3. **실적 입력**: 7일쯤 지나서 블로그 통계·제휴사 리포트 숫자를 넣어. 다른 채널에서 본 숫자면 '채널'을 골라줘 → 원고 화면에 **채널별 합계**가 생겨.
4. **검색 유입 키워드**: 블로그 통계의 유입 검색어를 복사해서 붙여넣어. 한 줄에 '검색어 숫자'(표에서 복사해도 돼). 저장 전에 읽은 결과를 보여주니 숫자가 맞는지 확인해줘.
   - 같은 기간을 다시 넣으면 검색어별로 숫자만 새로 바뀌어 (나눠서 붙여넣어도 돼).
   - **기간이 겹치는 다른 기록**(예: 19~25일을 넣었는데 20~26일을 또 넣음)이 있으면 저장 전에 알려줘. 겹친 채로 더하면 같은 유입이 두 번 세지니까, 확인하면 겹치는 기간의 검색어를 지우고 이번 것으로 저장해. 매주 겹치지 않게 7일씩 넣는 걸 권해.
   - 비율(%)은 유입 수가 아니라서 숫자로 안 써. 비율만 있으면 '숫자 없음'으로 저장되고, 추천(조회 3회 이상 같은 기준)에는 안 쓰여 — 원고 화면의 '제목·키워드에 없는 검색어' 알림에는 나와.
   - 끝의 숫자가 검색어의 일부일 수 있으면(예: "아이폰 16 12.5%") 유입 수로 읽지 않아. 미리보기에서 '숫자 없음'이면 확인해줘.
5. **개선안**: '개선안 요청'을 누르면 자동 작가가 다음 실행에 그 글의 실적·유입 검색어·다른 채널 기록을 보고 제목 후보·도입부·소제목·링크 위치를 써 둬. **올라간 글은 앱이 바꾸지 않아** — 마음에 드는 것만 블로그에서 직접 고쳐. 게시한 글 중 앱에 본문이 있는 글만 요청할 수 있어 (게시 기록만 직접 넣은 글은 본문이 없어서 안 돼).

## 개선 루프 (홈)

입력한 실적·유입 검색어·게시 기록으로 고른 규칙 기반 추천을 네 묶음으로 보여줘. 근거 숫자를 같이 보여주고, 근거가 약하면 '참고'로 표시해.

| 묶음 | 예 |
|---|---|
| 고칠 것 | 조회는 많은데 링크 클릭이 적음, 클릭은 많은데 구매가 없음, 실제로 들어온 검색어가 제목에 없음, 가격·출처 확인이 오래됨 → '개선안 요청' |
| 더 쓸 것 | 구매가 나온 글의 후속 글, 들어온 검색어인데 다룬 글이 없는 것, 반응이 있는데 다른 채널에 안 올린 글 |
| 그만할 것 | 들인 시간에 비해 수익이 적은 글, 30일 넘은 글 3개 이상이 클릭·구매·수익 모두 0인 카테고리 |
| 데이터 먼저 | 게시한 지 7일 지났는데 실적이 없는 글 |

## 최근 7일 정리 (홈)

최근 7일(오늘 포함)과 그 전 7일을 나란히 보여줘: 새 원고(자동 몇 개), 게시, 다른 채널에 올림, 넣은 검색어, 조회수·링크 클릭·발생 수익, 잘 된 글 3개, 자동 작가 실행 횟수, 다음에 할 것. 원고·게시·채널·검색어는 앱 기록(지운 글 빼고), 조회·클릭·수익은 입력한 실적이야. 실적이 없으면 0이 아니라 '데이터 없음'.

조회·클릭·수익은 **그 7일 안에 다 들어가는 실적만** 세. 한 달치처럼 기간이 긴 실적은 두 주에 똑같이 잡혀서 비교가 틀려지니까 빼고, 몇 줄 뺐는지 아래에 알려줘. 주간 비교를 보고 싶으면 실적을 7일 안의 기간(예: 하루·일주일 단위)으로 넣어줘. '이번 달 수익'·'최근 30일'은 지금처럼 기간에 걸친 실적을 다 세.

## 추천하는 하루·한 주

- **하루**: 홈 '지금 막힌 곳' 하나만 처리 (보통은 검수 1편 → 게시 → 게시 완료 기록 → 다른 채널 1곳).
- **일주일**: 7일 지난 글에 실적과 유입 검색어 넣기 → 개선 루프의 '고칠 것' 1~2개 개선안 요청 → '더 쓸 것'으로 다음 주제 정하기 → 최근 7일 정리 확인.

## 숫자에 대한 약속

- 앱은 블로그 통계·제휴사 실적·검색어를 **직접 가져오지 않아.** 사용자가 넣은 숫자만 써 (외부 사이트를 긁어오지 않음).
- 없는 숫자는 '데이터 없음'으로 보여주고 0으로 꾸미지 않아.
- 추천·개선안은 규칙과 들어온 숫자를 근거로 하고, 검색 순위나 수익을 보장하지 않아.
