# 글공장 1.3.1 정확성·신뢰성 개선 — 완료 보고서 (2026-10-26)

「글공장 1.3.1 정확성·신뢰성 개선 작업」 지시서 10장 '최종 제출' 순서대로 정리했어.

- 대상: 1.3.0(`299b06e`) → **1.3.1**. 전체 재작성 없이 기존 코드에 고쳐 넣었고, DB는 열 두 개만 더함(015). 코드는 저장소 가지 `release/1.3.1`에 있어.
- **배포 상태: 2026-10-26 배포함 (사용자 승인 뒤).** 작업을 보고할 때는 지시서 9장(실서비스 임의 배포 금지)에 따라 배포하지 않았고, 사용자가 '배포'라고 승인한 뒤 같은 날 DB 015 → 서버 → 앱 화면 → 예약 작업 → Claude 안 글공장 순서로 올렸어. 기록은 맨 아래 6번.
- 실데이터는 바꾸지 않았어. 실서버 DB는 읽기 조회만 했고(실제 원고가 새 판정에서 어떻게 나오는지 보려고), 읽은 원고 내용은 저장소·ZIP에 넣지 않았어. 테스트는 모두 모의 서버·로컬 DB·가짜 DB API에서 돌렸어.

## 5. 남은 한계와 향후 우선순위

한계
- 주력 주제 판정은 낱말 비교라서, 주제 안의 글이어도 키워드·제목에 주제 낱말이 없으면 '판단 어려움'·'주력 주제 밖'이 나와. 주력 주제 이름이 넓으면(예: '계절템·겨울 가전') 대부분 '판단 어려움'이 될 수 있어 → 설정의 '주력 주제 낱말'(예: 히터, 전기요, 온수매트, 가습기)로 보완.
- 숫자 기준(70%·3단어·링크 2개·앞 15%·하루 1편)은 앱 권장 기준이고, 검색량·경쟁도는 조회하지 않아.
- 사진 출처는 사용자가 고른 값을 믿어 (앱이 촬영자를 알 수는 없음). 예전에 올린 사진은 하나씩 출처를 골라야 '직접 촬영'으로 셈.
- 서버의 DB 015 전 대비는 가짜 DB API로만 확인했어 (배포는 015를 먼저 적용해서 실서버에서는 이 경로를 타지 않았어).
- 1.3.1 규칙으로 돌린 실제 예약 실행은 한 번(2026-10-27 오전 8:51, 자동 원고 1편)만 확인했어. 요청 원고·주제 추천·채널별 버전 작업, 제휴 링크 자리는 실제 실행으로 아직 확인 못 했어.
